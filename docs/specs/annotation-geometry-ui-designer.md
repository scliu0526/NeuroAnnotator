# 標註幾何、介面與 Designer 增量規格

## Problem Statement

使用者在 SEG 區域含多個空洞時，會得到每個空洞各自連至外圈的橋接，即使空洞之間有更短的合法連線。圖片放大後難以判斷目前視野在原圖的位置；框選填色、畫筆起點、中斷預覽、方向鍵與工具鍵盤操作的回饋也不足。工具圖示與提示文字未使用指定視覺資源，新增類別及標註集的流程不夠直接。維護者無法在 Visual Studio Designer 檢視大多數視窗與視覺控制項，現有程式碼也缺少一致的文件註解。

## Solution

將多空洞視為同一個空洞橋接網路，從外圈與全部空洞之間選出總長度最短的合法連通樹，並保留未經編輯的既有路徑。在圖片與標註畫布提供可互動縮圖，改善框選、畫筆起點及預覽、方向鍵移動與工具快捷鍵。工具與新增標註集使用指定圖示與統一文字，類別改為直接依最大 `classN` 編號新增。所有 Form 與具可見版面的 UserControl 轉為可由 Visual Studio Designer 開啟的標準結構，並為手寫正式程式碼補上繁體中文文件註解。

## User Stories

1. 身為 SEG 標註使用者，我希望多個空洞以整體最短的合法連線組合接通外圈，以便匯出緊湊且正確的路徑。
2. 身為 SEG 標註使用者，我希望空洞可連至另一個空洞，以便洞之間較接近時不必各自拉長線至外圈。
3. 身為 SEG 標註使用者，我希望每個空洞最終都有路徑接通外圈，以便 Non-Zero 填色與 JSON 路徑保持正確。
4. 身為 SEG 標註使用者，我希望系統排除穿出標註實體或穿過其他空洞的連線，以便橋接不破壞幾何語意。
5. 身為 SEG 標註使用者，我希望新增或編輯空洞時重新評估整體網路，以便既有連線在有更短方案時能更新。
6. 身為舊專案使用者，我希望未編輯的匯入路徑保持原樣，以便單純開啟或匯出不會改寫既有 JSON。
7. 身為 SEG 標註使用者，我希望等距時優先保留仍合法的既有連線，以便避免不必要的路徑跳動。
8. 身為 SEG 標註使用者，我希望無法產生合法網路時取消該次修改並收到提示，以便不會保存無法正確表示的空洞。
9. 身為放大圖片的使用者，我希望在畫布右上角看見縮圖與視野框，以便知道目前位置。
10. 身為放大圖片的使用者，我希望點擊縮圖可移到指定位置，以便快速導覽原圖。
11. 身為放大圖片的使用者，我希望拖曳縮圖的視野框可連續平移畫布，以便精確調整視野。
12. 身為畫布使用者，我希望收起縮圖並以小圖示重新開啟，以便在需要時留出更多畫布空間。
13. 身為畫布使用者，我希望圖片已完整顯示時隱藏縮圖與切換圖示，以便不出現無用遮擋。
14. 身為 OBD 或 SEG 標註使用者，我希望框選時只顯示明顯的黑色虛線邊緣，以便不用填色遮住圖片。
15. 身為 SEG 畫筆使用者，我希望起點平時是 8px 白色實心圓與黑色外框，以便在各種類別色上看清起點。
16. 身為 SEG 畫筆使用者，我希望滑鼠進入可閉環範圍時起點轉為類別色並稍微放大，以便知道點擊後會完成形狀。
17. 身為 SEG 畫筆使用者，我希望放開左鍵後末端預覽線繼續跟隨滑鼠，以便可繼續加點或返回起點閉環。
18. 身為圖片瀏覽使用者，我希望按一次上下鍵就能切換圖片，以便不需要重複按鍵。
19. 身為 OBD 或 SEG 標註使用者，我希望用方向鍵將所有已選區塊每次移動原圖 1px，以便精細調整位置。
20. 身為 OBD 或 SEG 標註使用者，我希望按住方向鍵可連續移動且一次 Undo 復原整段移動，以便快速調整又容易撤銷。
21. 身為多選標註使用者，我希望任一區塊將越界時整組停止，以便保持相對位置且不產生越界幾何。
22. 身為標註使用者，我希望有已選區塊時上下鍵移動區塊，沒有選取時才切換圖片，以便鍵盤行為可預期。
23. 身為標註使用者，我希望以 `V/B/P/C/R/E/L` 切換選取、筆刷、畫筆、圓形、矩形、橡皮擦與線形，以便不離開畫布即可換工具。
24. 身為標註使用者，我希望工具鍵只在目前標註類型支援時生效，以便 CLA、OBD 與 SEG 不會意外跳轉。
25. 身為正在繪製的使用者，我希望快捷鍵切換工具時取消未完成預覽，以便不留下半成品。
26. 身為輸入名稱的使用者，我希望文字欄位中的字母與方向鍵保留原用途，以便正常編輯文字。
27. 身為標註使用者，我希望滑鼠停在工具時看見「矩形 R」之類的名稱與快捷鍵，以便學會鍵盤操作。
28. 身為標註使用者，我希望工具提示不再特別標示 OBD 或 SEG，以便只專注於工具功能。
29. 身為標註使用者，我希望工具按鈕使用指定圖示，以便視覺識別一致。
30. 身為類別管理使用者，我希望按新增後直接建立下一個 `classN`，以便連續新增類別而不被對話框中斷。
31. 身為類別管理使用者，我希望新編號依現有完全符合小寫 `class` 加正整數的最大 N 加一，以便刪除、改名或跳號後仍不重用編號。
32. 身為新增標註集的使用者，我希望以圖示卡片選擇 CLA、OBD 或 SEG，以便直觀理解標註類型。
33. 身為新增標註集的使用者，我希望每張卡片顯示縮寫、中文名稱與簡短用途，以便選擇正確類型。
34. 身為新增標註集的使用者，我希望對話框不預選類型，且只在已選類型並輸入名稱時才能建立，以便減少誤建。
35. 身為 Visual Studio 維護者，我希望所有 Form 與可見 UserControl 都有 Designer 結構，以便在不執行程式的情況下檢視與調整版面。
36. 身為程式維護者，我希望所有手寫正式程式碼的型別與成員有繁體中文 XML 文件註解，以便快速理解用途。
37. 身為程式維護者，我希望關鍵判斷、演算法與狀態變更有簡潔的繁體中文註解，以便理解不直觀行為而不被重複程式的註解干擾。
38. 身為專案維護者，我希望本次修改在獨立分支與 Draft PR 驗證，以便在桌面驗收後再決定是否合併 `main`。

## Implementation Decisions

- 空洞橋接網路以外圈 O 與所有空洞為節點，合法候選線的權重是實際輪廓邊緣之間的最短距離；不使用中心點或外接矩形距離。
- 從候選線選出總長度最短的最小生成樹。空洞可互連，但所有空洞最終必須連通 O；不保留不必要的循環。
- 候選線必須在標註實體內，不得穿過其他空洞。最短線不合法時繼續搜尋下一條最短合法直線；本次不新增折線繞行。
- 新增空洞或幾何修改後重算整個網路。新舊空洞沒有距離優先權；等距時優先保留仍合法的既有連線，再以固定座標順序打破平手。
- 未修改的匯入路徑維持原點序與橋接。若無法使所有空洞合法連通 O，取消當次幾何修改、保留原標註、顯示提示，且不建立 Undo 記錄。
- 空洞橋接不得改變外圈、空洞形狀或填色面積；既有整數座標、Non-Zero Winding、Clipper2 與 JSON 契約維持不變。
- 縮圖使用原圖長寬比，限制在最大約 180×120 畫面像素，並依 Windows DPI 縮放。圖片只要有一軸無法完整顯示，圖片頁與標註頁右上角就顯示縮圖。
- 縮圖顯示目前視野框，點擊可定位，拖曳視野框可平移，且與捲軸、滾輪、右鍵拖曳與縮放共用同一視角邊界。縮圖可收起；狀態在本次程式執行期間跨圖片與標註集保留，重開後預設展開。圖片完整可見時縮圖與切換圖示都隱藏。
- OBD 與 SEG 拖曳框選只繪製不填色的 2px 黑色虛線矩形；選取完成後的物件外框與控制點維持既有行為。
- SEG 畫筆起點平時是約 8 畫面像素的白色實心圓與黑色外框。滑鼠進入現有 8 畫面像素閉環判定範圍時，起點改為目前類別色實心圓並放大至約 10 畫面像素。
- SEG 畫筆放開左鍵後保留已畫路徑，從最後一點到滑鼠的預覽線繼續跟隨。再按左鍵可繼續加點，點擊起點閉環；`Esc`、切換工具或離開操作情境取消整筆未完成標註。
- 方向鍵在 OBD 或 SEG 有已選物件時，將全部已選物件每次移動原圖座標 1px。按住鍵的連續移動合併為一次 Undo/Redo；任一物件將越界時整組不移動。
- 沒有已選標註時，上下鍵以一次按鍵切換上一張或下一張圖片。文字輸入欄位中不觸發畫布快捷鍵。
- `V`、`B`、`P`、`C`、`R`、`E`、`L` 分別切換選取、筆刷、畫筆、圓形、矩形、橡皮擦、線形。CLA 不接受工具鍵；OBD 只接受 `V`、`R`；SEG 接受全部指定鍵。不支援的鍵靜默忽略。切換工具前取消未完成預覽。
- 工具提示統一為「選取 V」、「筆刷 B」、「畫筆 P」、「圓形 C」、「矩形 R」、「橡皮擦 E」、「線形 L」，不加 OBD 或 SEG 前綴。圖示作為嵌入式程式資源，發佈後不依賴原始檔案路徑。
- 新增類別不開啟名稱對話框。只有完全符合小寫 `class` 加無前導零正整數的名稱參與編號；取最大 N 建立 `class(N+1)`，沒有匹配項時建立 `class1`。
- 新增標註集對話框只顯示 CLA、OBD、SEG 三張類型卡片，每張使用指定圖示，並顯示縮寫、中文名稱與簡短用途。本次不新增描述欄位與其他標註類型。開啟時不預選卡片；已選卡片且名稱不為空白時才可建立。
- 所有 Form 與承載可見版面的 UserControl 改為標準 partial class 與 Designer 結構。動態標註、圖片及自繪內容仍在執行時產生，不為了 Designer 複製業務邏輯。
- 所有手寫正式程式碼中的函式（包含建構函式）使用繁體中文 XML 文件註解（`///`），並說明契約、參數、返回值、副作用與例外。類別、列舉、屬性、事件及重要欄位使用一般單行註解（`//`）。關鍵判斷、演算法與狀態變更加上簡潔單行註解；不對簡單賦值、括號或顯然返回逐行重述。Designer、資源自動產生碼、建置輸出與測試程式排除。
- 不變更專案資料庫或 JSON 交換結構。縮圖收合、目前工具與鍵盤連發群組都是執行期 UI 狀態。
- 修改維持在 `annotation-geometry-ui-designer` 分支，以指向 `main` 的 Draft PR 提供審查。自動測試、CI 與桌面驗收是不同證據關卡；只有使用者另行明確指示才合併 `main`。

## Testing Decisions

- 好的測試驗證使用者可觀察的幾何、畫面、鍵盤互動、持久化與 Undo/Redo 結果，不把特定私有函式或控制項存在當作唯一成功條件。
- 測試接縫優先沿用現有 SEG 幾何核心、畫布控制項、主視窗互動、專案儲存與 JSON 往返整合測試。縮圖與鍵盤群組以畫布或主視窗層級驗證，不為每個內部步驟建立新接口。
- 空洞橋接網路測試覆蓋兩洞的外圈分接與洞間串接、三洞以上的最小生成樹、洞連洞後接通 O、凹形外圈、其他洞阻擋、不合法邊排除、等距保留既有邊、固定平手順序與無法連通的失敗保護。
- 幾何測試同時比較外圈與空洞形狀、填色面積、Non-Zero 遮罩、整數端點、網路總長與結果穩定性。未修改匯入路徑必須逐點一致；編輯後的路徑必須在儲存、重開、Undo/Redo 與 JSON 往返後維持語意。
- 效能測試維持 17,000 點單洞橋接 1 秒內的既有門檻，並增加總輪廓約 17,000 點、最多 10 個空洞在 2 秒內完成的目標。
- 縮圖測試覆蓋只在圖片超出畫布時顯示、橫圖與直圖的長寬比、最大尺寸、視野框映射、點擊定位、拖曳平移、邊界限制、收合狀態、切圖、切頁與重啟預設。
- 畫布渲染測試覆蓋 OBD／SEG 無填色 2px 黑色虛線框選，畫筆 8px 白色實心黑框起點、可閉環時的類別色約 10px 圓點，以及放開左鍵後持續跟隨的末端預覽。
- 鍵盤測試覆蓋上下鍵單次切圖、有選取時的 OBD／SEG 四向 1px 移動、多選相對位置、長按群組、單次 Undo/Redo、整組越界停止、文字焦點，以及各標註類型支援或忽略的工具鍵。
- 工具與類別測試覆蓋圖示資源完整性、每個提示的精確名稱與鍵位、切換時取消未完成預覽，以及 `classN` 的空集合、連續編號、跳號、刪除、改名、大小寫、前導零與自訂名稱。
- 新增標註集測試覆蓋三種卡片、無預選、非空白名稱、建立按鈕狀態、取消與建立後的類型。
- Designer 驗收須在 Visual Studio 逐一開啟所有 Form 與可見 UserControl，確認沒有設計器錯誤且主要控制項可見。這是桌面手動驗收，建置成功不能取代。
- 介面桌面驗收在 100%、150%、200% DPI 檢查縮圖、收合圖示、工具圖示、虛線框選、類型卡片、鍵盤連發與畫筆閉環回饋。
- 全部自動測試、Release x64 建置、CI、Visual Studio Designer 驗收與 Windows 桌面操作分別記錄結論；任一項不取代其他關卡。

## Out of Scope

- 在 CLA、OBD、SEG 之外新增 PAC、OCR、ROT、GAN 或異常學習類型。
- 為標註集新增描述欄位、資料庫欄位或 JSON 契約。
- 將縮圖展開狀態、目前工具或鍵盤移動群組寫入專案或使用者設定。
- 以折線、曲線或導航網格繞過無法直接連線的 SEG 障礙。
- 對 Designer 自動產生程式逐行加註解，或為簡單賦值與括號重述程式碼。
- 為測試程式、建置輸出、資源自動產生碼補齊 XML 文件註解。
- 在使用者完成桌面與 Designer 驗收並明確指示前合併 `main`。

## Further Notes

- 本規格補充既有標註介面、SEG 效能與畫布互動規格；未明確取代的專案、幾何、持久化與 JSON 契約繼續適用。
- 提供的工具與標註類型圖示納入專案；新增標註集的參考畫面只作為本次設計輸入，不納入提交。
- 功能修改、Designer 搬移與全面文件註解應拆成可獨立審查的提交，以避免大型機械式變更遮蔽行為差異。
