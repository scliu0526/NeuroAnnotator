# 標註介面與匯入工作流程增量規格

## Problem Statement

使用者無法從 Visual Studio Designer 的屬性視窗追蹤多數固定控制項使用的事件，且大量手寫函式的文件註解格式不一致。SEG 使用者必須切換到橡皮擦才能移除標註，無法以原工具的幾何範圍快速擦除。圖片、資料夾與標註 JSON 匯入入口藏在選單中，也不能在既有匯入執行時先排入後續工作或回查某次匯入的圖片。資料集操作集中在清單上方，難以對照清單；類別按鈕以整面類別色呈現，類別名稱與選取狀態不夠清楚。

## Solution

將 Designer 屬性視窗可見的固定控制項事件改由 Designer 接線，並以一致的繁體中文 XML 文件註解整理所有手寫正式函式。SEG 的矩形、圓形、畫筆、筆刷與線形在完成時按住 Ctrl 便以相同幾何擦除目前類別，游標以右下角的加減符號預告結果。三種匯入改為頁面按鈕並共用一個專案範圍的 FIFO 匯入佇列，以可管理的垂直卡片視窗顯示狀態、進度、取消、結果與批次圖片導覽。資料集操作移到清單右側並新增切分所選／切分全部；類別列改為圓角色塊、名稱與獨立選取提示。

## User Stories

1. 身為 Visual Studio 維護者，我希望固定控制項的事件可在 Designer 屬性視窗中看見，以便理解畫面使用了哪些事件。
2. 身為 Visual Studio 維護者，我希望雙擊屬性視窗中的事件可跳到具名處理函式，以便快速閱讀與修改功能。
3. 身為程式維護者，我希望 Designer 看不到的自訂事件維持既有接線方式，以便不為了設計器可見性改造穩定的控制項 API。
4. 身為程式維護者，我希望每個手寫正式函式與建構函式都有一致的繁體中文 XML 文件，以便從 IntelliSense 理解契約。
5. 身為程式維護者，我希望函式摘要、參數、回傳值與例外分行顯示，以便長文件仍易讀。
6. 身為程式維護者，我希望完全沿用介面或基底契約的實作可使用 `inheritdoc`，以便避免重複文件逐漸不一致。
7. 身為 SEG 使用者，我希望矩形完成時按住 Ctrl 可擦除矩形範圍，以便不切換工具便能修正標註。
8. 身為 SEG 使用者，我希望圓形完成時按住 Ctrl 可擦除圓形範圍，以便快速挖除圓形區域。
9. 身為 SEG 使用者，我希望畫筆閉合時按住 Ctrl 可擦除多邊形範圍，以便精確移除不規則區域。
10. 身為 SEG 使用者，我希望筆刷放開左鍵時按住 Ctrl 可擦除整筆預覽軌跡，以便連續修邊。
11. 身為 SEG 使用者，我希望線形完成時按住 Ctrl 可擦除該寬度的線段，以便快速切開狹長區域。
12. 身為 SEG 使用者，我希望只有完成動作當下的 Ctrl 狀態決定整筆新增或擦除，以便途中按鍵變化不把單一形狀拆成多次操作。
13. 身為 SEG 使用者，我希望 Ctrl 擦除只影響目前類別，以便重疊的其他類別保持不變。
14. 身為 SEG 使用者，我希望擦除只移除幾何重疊部分並保留合法碎片與空洞，以便不因輕微碰觸刪除整個區域。
15. 身為 SEG 使用者，我希望擦除沒有命中時不產生 Undo 記錄或提示，以便連續操作不被無效歷史干擾。
16. 身為 SEG 使用者，我希望標註隱藏時仍能使用 Ctrl 擦除與橡皮擦，以便在原圖檢視下依預覽修整標註。
17. 身為 SEG 使用者，我希望矩形、圓形與畫筆的十字游標右下角在 Ctrl 按住時顯示 `−`，以便知道完成後會擦除。
18. 身為 SEG 使用者，我希望筆刷與線形的圓環右下角平時顯示 `+`、Ctrl 時顯示 `−`，以便辨認下一筆效果。
19. 身為 SEG 使用者，我希望橡皮擦圓環的 `−` 也位於右下角，以便所有工具的符號位置一致。
20. 身為 SEG 使用者，我希望 Ctrl 擦除仍顯示目前類別的 40% 幾何預覽，以便看清實際影響範圍。
21. 身為圖片管理使用者，我希望在圖片分頁清單上方直接看到「匯入圖片」與「匯入資料夾」，以便不必進入選單尋找。
22. 身為標註管理使用者，我希望在標註頁的標註集操作列直接看到「匯入標註 JSON」，以便入口與標註資料靠近。
23. 身為使用者，我希望舊的三個匯入選單入口移除，以便同一功能不出現重複入口。
24. 身為使用者，我希望沒有開啟專案時匯入按鈕停用，以便不會按下後沒有反應。
25. 身為大量匯入使用者，我希望第一個匯入執行時仍可選擇並排入後續圖片、資料夾或 JSON，以便不必等待每一批完成才操作。
26. 身為大量匯入使用者，我希望三種匯入依加入順序一次執行一項，以便同一專案不發生平行寫入競爭。
27. 身為使用者，我希望每筆匯入要求被稱為匯入工作並具有一致狀態，以便理解佇列進度。
28. 身為使用者，我希望最多只有十筆等待中或執行中的匯入工作，以便誤操作不會建立無界佇列。
29. 身為使用者，我希望最近二十筆已完成、失敗或取消工作保留在目前專案工作階段，以便回查結果。
30. 身為使用者，我希望來源路徑與選項在排隊時被保存、內容在執行時才讀取，以便排隊本身不複製大量檔案或阻塞介面。
31. 身為使用者，我希望來源在等待期間被移動、刪除或修改時，工作依執行時狀態成功或失敗並留下結果，以便不使用隱藏暫存副本。
32. 身為使用者，我希望非致命失敗或單項取消後佇列繼續下一筆，以便一個壞來源不阻止其他工作。
33. 身為使用者，我希望等待中的匯入工作可以直接取消，以便移除尚未開始的錯誤選擇。
34. 身為使用者，我希望執行中的圖片或資料夾工作可要求取消並保留已成功匯入部分，以便長批次能安全停止。
35. 身為使用者，我希望 JSON 開始寫入後不可中途取消，以便整份標註保持原子成功或失敗。
36. 身為使用者，我希望佇列存在時不能更換專案，以便所有排隊工作保持相同目標。
37. 身為標註使用者，我希望匯入期間仍能瀏覽和編輯既有單張圖片，以便等待時仍能工作。
38. 身為專案維護者，我希望匯入期間停用刪除、切分、匯出、備份還原等全域或批次命令，以便避免與背景匯入競爭。
39. 身為使用者，我希望關閉程式時看見執行中與等待中數量，並能安全取消可取消工作，以便不會突然中斷專案寫入。
40. 身為使用者，我希望 JSON 正在原子寫入時程式等待安全完成後才關閉，以便資料不會半寫入。
41. 身為使用者，我希望匯入佇列以可獨立操作的非強制回應視窗呈現，以便一邊查看工作一邊繼續使用主視窗。
42. 身為使用者，我希望第一筆工作加入時自動開啟佇列視窗，關閉後可由專案選單重新開啟，以便隨時查看。
43. 身為使用者，我希望每個匯入工作以垂直卡片顯示類型、來源、狀態、進度、摘要與操作，以便快速理解。
44. 身為使用者，我希望錯誤或完整結果可在卡片內展開與收合，以便平時保持精簡、需要時查看細節。
45. 身為使用者，我希望可以清除已結束工作，但不影響等待中或執行中的工作，以便整理歷史。
46. 身為使用者，我希望圖片或資料夾工作完成後可按「查看匯入圖片」，以便直接看見該批成功匯入內容。
47. 身為使用者，我希望查看匯入圖片時自動清除阻擋的搜尋或篩選並選取整批仍存在圖片，以便不遺漏結果。
48. 身為使用者，我希望已刪除的匯入圖片被靜默忽略，而全批皆刪除時查看按鈕停用並說明原因，以便歷史卡片不指向不存在資料。
49. 身為資料集管理使用者，我希望操作按鈕與比例欄位位於清單右側，以便一邊查看清單一邊操作。
50. 身為資料集管理使用者，我希望右側操作依隨機切分、手動分配與 Dataset Retest 分組並附簡短說明，以便理解各區用途。
51. 身為資料集管理使用者，我希望可選擇切分明確反白的圖片，以便只重新分配指定子集。
52. 身為資料集管理使用者，我希望可選擇切分全部可用圖片，以便保留原本的全專案自動切分能力。
53. 身為資料集管理使用者，我希望切分所選沒有選取時不可執行，以便避免誤把可見列或全部圖片當成目標。
54. 身為資料集管理使用者，我希望切分所選仍使用既有 test 最低數與每類 train 保留規則，以便兩種切分只在範圍不同。
55. 身為資料集管理使用者，我希望切分所選不改變範圍外的 train、test、未分配或 not_used 狀態，以便局部操作可預期。
56. 身為資料集管理使用者，我希望 Train／Test、未分配／不使用各自並排，Retest 獨立成區，以便操作密度接近參考版面。
57. 身為資料集管理使用者，我希望右側只提供設為 Retest，清除 Retest 仍在右鍵選單，以便維持既有操作分工。
58. 身為類別管理使用者，我希望類別顏色以圓角矩形顯示、名稱位於右側，以便顏色與文字都容易辨識。
59. 身為類別管理使用者，我希望目前類別以淡色列背景與左側強調線表示，以便選取狀態不與類別顏色混淆。
60. 身為類別管理使用者，我希望點擊色塊、名稱或列空白都能選取類別，以便整列都有一致的點擊範圍。
61. 身為類別管理使用者，我希望長名稱單行省略並以 ToolTip 顯示全文，以便列高一致又能查看完整名稱。
62. 身為類別管理使用者，我希望重新命名、改色與刪除仍由整列右鍵選單提供，以便既有管理方式不變。
63. 身為專案維護者，我希望功能修改、全面文件註解與機械式事件搬移分開提交，以便審查行為差異。
64. 身為專案維護者，我希望自動測試、Release 建置、CI、Designer、Windows 操作及 DPI 驗收分開記錄，以便一種證據不取代另一種。
65. 身為專案維護者，我希望工作在獨立分支與 Draft PR 中進行，並只在使用者明確確認後合併 main，以便保護主線。

## Implementation Decisions

- Designer 搬移只涵蓋 Visual Studio 屬性事件頁可見的固定控制項。事件訂閱由 Designer 產生或保存，處理邏輯使用一般程式碼中的具名函式。執行時動態物件與屬性頁不可見的自訂 `Action` 事件維持程式接線，不改成新的事件參數 API。
- 所有正式手寫函式與建構函式使用繁體中文 XML 文件註解；摘要採多行格式，參數、回傳與實際可擲例外各自說明。完全沿用介面或基底契約的實作可使用 `inheritdoc`。Designer、資源自動產生碼、建置輸出與測試程式排除。
- Ctrl 擦除只套用 SEG，OBD 與選取模式原行為不變。矩形、圓形、畫筆、筆刷、線形均先維持完整預覽，再於各自完成事件讀取當下 Ctrl 狀態；一筆操作不得在途中切成新增與擦除兩段。
- Ctrl 擦除使用工具本身的實際幾何對目前類別做差集：矩形、橢圓、多邊形使用填色面積，筆刷與線形使用落筆時鎖定的筆畫寬度。差集沿用既有 SEG 整數座標、Non-Zero、碎片、空洞、橋接與同類別隔離契約。無實際變更時不形成完成操作。
- 標註隱藏不阻止 Ctrl 擦除或橡皮擦；當次預覽仍可見並沿用目前類別 RGB 與固定 40% alpha。這是對先前「隱藏時不可編輯既有標註」規則的明確例外，只限幾何擦除，不恢復既有物件命中、選取或變形。
- 游標符號使用畫面座標與 DPI 可讀尺寸。矩形、圓形、畫筆保留十字，Ctrl 時在右下角加 `−`；筆刷與線形保留寬度圓環並在右下角顯示 `+` 或 `−`；橡皮擦的 `−` 固定在右下角。符號不得遮蔽實際落點。
- 三個舊匯入選單入口移除。圖片與資料夾按鈕位於圖片清單上方，標註 JSON 按鈕位於標註頁標註集管理操作之後；按鈕使用清楚文字而不新增圖示。沒有專案時停用。
- 匯入工作是單次圖片清單、資料夾或標註 JSON 匯入要求。工作固定隸屬加入時的專案工作階段，狀態為等待中、執行中、已完成、失敗或已取消。三種類型共用單一 FIFO，任何時刻最多一項寫入專案。
- 等待中與執行中合計上限十筆；到達上限時拒絕新增並提示。已結束歷史最多二十筆，超過時只淘汰最舊的已完成、失敗或取消項目，不影響等待或執行工作。
- 圖片工作在排隊時保存明確檔案路徑，資料夾工作保存路徑及是否遞迴，JSON 工作保存檔案路徑；內容於輪到執行時才讀取。來源漂移以該工作失敗或部分成功呈現，不建立隱藏快照。
- 圖片與資料夾工作沿用每檔交易、部分成功與取消契約；執行中可要求取消。JSON 工作沿用整批原子寫入，開始寫入後取消操作停用。單項非致命失敗或取消不停止後續工作；只有專案無法安全寫入等致命狀態才停止佇列。
- 佇列未清空時禁止建立、開啟、另存或更換專案。圖片瀏覽、頁面切換與既有單張圖片標註可繼續；刪圖、資料集批次操作、匯出、備份還原及其他會與專案全域狀態競爭的命令停用。三個匯入入口保持可用直到十筆上限。
- 關閉應用程式時顯示執行中與等待中數量。使用者確認後清除等待工作、要求取消可取消工作；若 JSON 已進入原子寫入則等安全完成再關閉。使用者取消關閉時工作不變。
- 匯入佇列為單一 modeless 視窗，第一筆加入時自動顯示，關閉只隱藏介面；專案選單提供重新開啟入口。視窗以可捲動的動態卡片呈現，卡片自身為 Designer 可開啟的可見 UserControl；卡片實例與佇列的動態接線屬自訂事件例外。
- 每張卡片顯示類型、來源、狀態、等待順位或進度、結果摘要與適用操作。詳細資料可展開／收合。等待工作可取消；圖片／資料夾執行中可要求取消；JSON 寫入中與已結束工作不可取消。視窗提供只清除已結束項目的命令。
- 圖片與資料夾工作保存實際成功新增的圖片 ID。已完成或部分成功且至少一張仍存在時顯示「查看匯入圖片」；按下後切到圖片頁、清除阻擋搜尋／篩選、以這批仍存在圖片取代目前選取、捲至第一張並在畫布顯示。已刪除圖片靜默忽略；全部不存在時按鈕停用並以 ToolTip 說明。
- 資料集頁使用左側篩選與清單、右側固定操作欄。右欄以繁體中文標題與簡短說明分成隨機切分、手動分配與 Dataset Retest；在低解析度或高 DPI 下允許右欄內容垂直捲動，不得遮住清單。
- 自動切分新增明確目標範圍。切分所選只接受清單中明確選取的圖片 ID，沒有選取時停用；切分全部接受目前標註集的所有可用圖片。兩者共用既有隨機、test 至少三張、可行時每類保留十張 train 與警告規則。切分所選的交易及 Undo 只覆寫目標範圍，範圍外狀態與 Retest 保持。
- 手動分配第一列為 Train／Test，第二列為未分配／不使用；Retest 獨立區只提供設為 Retest，清除 Retest 維持清單右鍵命令。比例欄位及切分所選／全部位於隨機切分區。
- 類別列不再以整面類別色填滿。每列顯示 DPI 縮放的圓角色塊、右側單行名稱、淡色選取背景與左側系統強調色線。長名稱以省略號及 ToolTip 顯示全文；整列選取語意及右鍵管理功能不變。
- 不變更專案資料庫結構或 JSON 交換格式。匯入佇列與歷史是本次程式執行中的 UI／應用狀態，不跨應用程式重啟持久化。
- 工作分支為 `annotation-ui-workflow-refresh`，從最新主線建立。第一個可審查差異推送至同一 Draft PR；自動測試、CI、Designer 與桌面驗收分別記錄，只有使用者明確指示才合併主線。

## Testing Decisions

- 好的測試驗證可觀察行為、幾何結果、專案資料、操作歷史與視窗狀態，而不是鎖定私有方法或為每個內部步驟建立接口。優先在最高既有接縫驗證：SEG 幾何核心、專案工作階段／儲存整合、資料集規劃器、畫布／主視窗互動及 WinForms 版面測試。
- 匯入 FIFO 新增一個最高層工作生命週期接縫，接受不可變的匯入工作描述並發布狀態快照；檔案匯入器、JSON 匯入器與專案交易仍沿用現有接縫，不把佇列狀態散落到每種匯入實作。
- SEG 測試覆蓋五種工具在完成瞬間 Ctrl 按下／放開的矩陣、途中 Ctrl 變化、目前類別與其他類別重疊、碎片、洞、邊界、無命中、標註顯示／隱藏、一次 Undo/Redo、儲存重開與 JSON 語意。幾何以遮罩、區域數與面積驗證，不只比較點序。
- 游標渲染測試覆蓋十字、寬度圓環、右下角 `+`／`−`、縮放與 DPI；桌面驗收確認符號不遮落點且按鍵狀態變化能立即重繪。
- 匯入工作測試覆蓋三種類型 FIFO、任何時刻單一執行、十筆上限、二十筆歷史淘汰、來源消失、非致命失敗續跑、致命停止、等待取消、圖片部分成功取消、JSON 原子性、專案切換鎖、關閉協調與命令啟用矩陣。
- 佇列 UI 測試覆蓋單一 modeless 視窗、重開入口、卡片狀態、順位、進度、展開詳細資料、取消按鈕狀態、清除已結束項目、捲動及 Designer 開啟。圖片導覽測試以保存的圖片 ID 驗證篩選清除、整批多選、第一張顯示、部分刪除靜默忽略與全刪除停用。
- 資料集測試沿用規劃器與專案儲存整合案例，新增切分所選／全部範圍、無選取停用、缺失圖片、既有警告、Retest 保留、範圍外完全不變、單一 Undo/Redo 及確認訊息實際張數。
- 類別列與頁面配置沿用既有主視窗版面測試，驗證色塊與名稱相對位置、選取提示、長名稱省略、右鍵功能、匯入按鈕位置、舊選單移除、資料集左右欄 containment 與非零清單寬度。
- Designer 驗收逐一開啟受影響 Form 與可見 UserControl，確認無設計時例外。對屬性事件頁可見的固定控制項，核對事件名稱存在且雙擊能跳至具名處理函式；不可見的自訂事件列為明確例外。
- XML 文件註解驗收盤點所有正式手寫函式與建構函式，確認完整多行文件或合法 `inheritdoc`，並排除 Designer、產生碼與測試。文件變更獨立提交，建置與 IntelliSense 無無效 XML。
- 執行 Release x64 建置、全部非互動測試與 GitHub Actions。Windows 桌面另在 1366×768 與一般桌面尺寸、100%、150%、200% DPI 驗收游標、按鈕、佇列卡片、資料集右欄、類別列與 Designer；CI 綠燈不取代桌面驗收。

## Out of Scope

- 將 OBD 的 Ctrl+矩形改成局部擦除、刪除碰到的 OBD 物件，或改變 OBD 軸對齊矩形契約。
- 在同一筆未完成幾何中依 Ctrl 變化切成新增與擦除片段。
- 改變擦除目標為全部類別，或在無命中時建立歷史／顯示提示。
- 將自訂 `Action` 事件全面改成 `EventHandler<TEventArgs>`，或把執行時資料項目硬編成固定 Designer 控制項。
- 為 Designer、自動產生資源碼、測試或建置輸出補齊 XML 文件註解。
- 平行執行匯入工作、持久化匯入佇列／歷史、工作重新排序、重試、暫停、跨專案佇列或永久匯入稽核紀錄。
- 在排隊時複製來源內容至暫存快照，或允許 JSON 原子寫入中途取消。
- 新增資料集切分單位、保存亂數種子，或改變既有最低 test／每類 train 規則。
- 改變類別名稱、顏色資料契約或類別右鍵管理語意。
- 在使用者完成 Designer、Windows 與 DPI 驗收並明確指示前合併主線。

## Further Notes

- 本規格補充既有圖片匯入、標註介面、畫布互動與資料集分配規格；衝突處以本規格為準，未提及的專案、幾何、持久化與 JSON 契約持續適用。
- 匯入工作與匯入佇列是本次新增的正式領域詞彙；序列化專案寫入的理由另由 ADR 記錄。
- 標註隱藏時允許 Ctrl 擦除與橡皮擦，是對既有隱藏互動規則的刻意例外，也是桌面驗收的高風險案例。
- 匯入佇列、全面文件註解、Designer 接線、Ctrl 擦除及介面重排應拆成可獨立審查的提交，避免大型機械差異遮蔽行為改動。
