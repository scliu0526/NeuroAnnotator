# 標註介面、SEG 效能與空洞橋接增量規格

## Problem Statement

目前圖片與標註頁的圖片清單、預覽與畫布分離，切換圖片需要往返頁籤；工具佔用畫布上方高度，快捷鍵、縮放狀態、標註數量及透明度的操作回饋不足。SEG 畫筆或筆刷在完成圖形時可能讓視窗卡住；空洞橋接使用輪廓首點，未連接最近的合法邊緣位置。使用者需要在不改變既有標註資料語意的前提下，順暢完成逐張標註並可驗證效能。

## Solution

圖片與標註頁共用左側圖片清單、目前圖片和畫布視角；畫布上方放縮放控制，右側放依 CLA、OBD、SEG 型別顯示的類別與圖示工具。補齊鍵盤選圖、多選、倍率顯示、平移邊界、透明度與線寬操作，並在資料集分配頁顯示目前標註集的物件數。量測並修正 SEG 完成路徑，讓運算期間介面持續回應、操作依序安全儲存；新生成或編輯後重新生成的空洞使用最短合法邊緣橋接。所有修改先放在 `annotation-ui-seg-performance` 分支，以 Draft PR 供使用者親自驗收。

## User Stories

1. 身為使用者，我希望圖片頁的左側常駐圖片清單、右側顯示圖片，以便一邊瀏覽一邊選圖。
2. 身為使用者，我希望標註頁也常駐同一份左側圖片清單，以便完成一張後直接選下一張。
3. 身為使用者，我希望兩頁同步目前圖片、倍率和平移位置，以便切頁後繼續查看同一處。
4. 身為使用者，我希望在兩頁非文字輸入狀態按上下鍵依可見清單順序切圖，以便不必先點清單。
5. 身為使用者，我希望搜尋或篩選暫時排除目前圖片時仍保留畫布，以便輸入過程不反覆跳圖。
6. 身為使用者，我希望標註頁按 Ctrl+A 選取目前圖片與目前標註集的所有 OBD 物件或 SEG 區域，以便批次操作，包括暫時不在視窗內的物件。
7. 身為使用者，我希望在選取模式按 Ctrl+左鍵逐一加入或移除 OBD 物件與 SEG 區域，以便精確多選。
8. 身為使用者，我希望在非文字輸入狀態按 F 切到適合視窗，以便快速恢復全圖檢視。
9. 身為使用者，我希望縮放時即時看到實際倍率百分比，以便知道目前影像尺度。
10. 身為使用者，我希望適合視窗及固定百分比選項位於圖片上方，以便就近調整。
11. 身為使用者，我希望圖片邊緣到達視窗邊界後不能繼續向外平移，以便畫布不露出無謂空白。
12. 身為使用者，我希望圖片小於視窗的方向保持置中，以便不會把小圖拖偏。
13. 身為使用者，我希望標註頁畫布比目前高至少約 25%，且圖片頁顯示區同尺寸，以便有更多有效檢視空間。
14. 身為使用者，我希望新增標註集成功後立即切到該標註集，以便直接開始標註。
15. 身為使用者，我希望 CLA 只呈現類別，OBD 呈現矩形與選取模式，SEG 呈現矩形、圓形、畫筆、筆刷、線型、橡皮擦與選取模式，以便只看到可用工具。
16. 身為使用者，我希望 OBD 或 SEG 標註集開啟時預設選取模式，以便點畫布不會誤建圖形。
17. 身為使用者，我希望圖像右側以圖示呈現工具並在滑鼠停留時顯示名稱，以便快速識別工具。
18. 身為使用者，我希望新增類別按鈕在類別清單上方，以便先看到建立入口。
19. 身為使用者，我希望 SEG 筆刷、線型與橡皮擦共用一個寬度值，以便切工具後筆寬一致。
20. 身為使用者，我希望筆刷與線型的預覽軌跡寬度等於完成後的結果，以便落筆前判斷覆蓋範圍。
21. 身為使用者，我希望以滑條調整 OBD 填色及 SEG 填色、筆刷和線型結果的透明度，以便看見影像與重疊標註。
22. 身為使用者，我希望標註外框、類別名稱及選取控制點保持清楚，以便低透明度下仍能操作。
23. 身為使用者，我希望切換標註集或重新開啟專案時透明度回到預設值，以便每次進入有一致起點。
24. 身為使用者，我希望資料集分配頁在 OBD、SEG 標註集顯示每張圖的標註數量，以便辨識空圖與密集標註圖片。
25. 身為使用者，我希望此數量隨合併、擦除分裂、刪除及 Undo/Redo 更新，以便數字對應目前實際可選取、可匯出的物件。
26. 身為使用者，我希望 SEG 畫筆或筆刷完成時視窗仍可回應，以便不會誤以為程式無回應。
27. 身為使用者，我希望處理中的切圖要求在標註安全儲存後執行，以便不遺失或錯存筆畫。
28. 身為使用者，我希望新生成的空洞從內外輪廓最近的合法邊緣點橋接，以便匯出的路徑符合預期。
29. 身為使用者，我希望未經編輯的既有匯入路徑保持原始點序，以便重匯出不因新版橋接規則而改寫資料。
30. 身為使用者，我希望在 GitHub Draft PR 檢查實作、測試與效能證據，並親自確認後才合併，以便控制 `main` 的變更。

## Implementation Decisions

- 附圖是左右欄、控制列與視覺層級參考；不增加圖中訓練、模型、自動標記等其他功能。
- 圖片與標註頁共用圖片選取、縮放倍率與平移位置；圖片頁維持原圖檢視，標註頁顯示目前標註集的疊圖。資料集分配頁維持獨立的批次清單。
- 上下鍵依目前搜尋、篩選與排序後的可見清單移動；文字輸入控制項保留原按鍵功能。當原圖被篩掉時，畫布留在原圖、清單可無選取列；下一次清單選取或非文字輸入時按上下鍵才切到可見結果。
- 切換圖片、頁面或標註集時沿用既有規則：尚未完成的形狀捨棄，已完成的操作保留。SEG 完成運算期間接受並記住切圖意圖，待成功儲存後才切換；儲存失敗須清楚回報，不可把筆畫錯存到新圖片。
- Ctrl+A 在標註頁且未輸入文字時選取目前圖片、目前標註集的全部 OBD 或 SEG 物件；CLA 不作區塊多選。Ctrl+左鍵多選只在選取模式生效；文字欄位的 Ctrl+A 保留全選文字。
- F 在非文字輸入狀態啟用適合視窗。實際倍率在縮放、適合視窗、換圖及視窗尺寸變動後立即更新；適合視窗模式仍顯示當下的實際百分比。
- 每一軸獨立限制平移：圖片縮放後不大於視窗時置中並鎖定該軸；大於視窗時限制至圖片邊緣，不因滾輪、拖曳、縮放或改變視窗大小而越界。
- 正常視窗尺寸下畫布高度至少比現況多約 25%；兩頁圖片顯示區同尺寸。在 1366×768、100%～200% DPI 下保留左側清單與右側工具可見，必要時縮窄欄位並讓內容捲動，不以 25% 增高作小尺寸門檻。
- 工具依選定標註集型別顯示；OBD、SEG 進入時預設選取模式。工具在圖像右側用圖示與懸停提示表示，新增類別入口位於類別清單上方。
- SEG 三種有寬度的工具共用原圖 1～100 整數像素設定，預設 15；單次程式工作階段記住此共同值。預覽與完成幾何採同一寬度語意，包含縮放後的顯示寬度。
- 透明度滑條預設 40%。OBD 填色、SEG 填色、筆刷及線型結果使用此值；外框、類別名稱與選取控制點保持可辨識。切換進任何標註集或重新開啟專案即重設為預設值，不寫入專案或 JSON。
- 資料集分配頁的數量只在 OBD、SEG 型別顯示，計算目前標註集與圖片中實際存在的 OBD 物件或 SEG 區域；不是畫筆操作次數、類別數或面積。合併及擦除後以結果物件數計算。
- SEG 空洞橋接只作用於新生成或幾何編輯後重新生成的區域。從內外輪廓邊段選擇最短且不穿出實體、不穿過其他空洞的合法連線，必要時插入邊上端點；同距離情形採穩定、可重現的選擇。橋接往返路徑維持 Non-Zero Winding 下的填色與空洞語意。未修改匯入路徑不重新橋接。
- 先量測 SEG 完成路徑再修正瓶頸。任何非同步運算不得讓同一專案的 SQLite 連線遭並行存取；幾何結果、資料交易、Undo 記錄與畫布更新必須依同一完成操作保持一致。
- 以目前 Windows 電腦的 Release x64 版本量測，目標是所有有效筆畫都在 1 秒內完成；本次驗收先以現有素材及約 17,000 點壓力案例逐筆檢查。超出已驗收工作量的案例仍須保持介面回應，不能宣稱已全面通過 1 秒門檻。
- 本次可在本機唯讀使用既有真實圖片與 SEG 素材量測；不得把真實內容放入 CI、PR 附件或驗收 ZIP。這項素材例外只適用本次工作。
- 修改在 `annotation-ui-seg-performance` 分支完成並推送 GitHub；以 Draft PR 呈現差異與證據。只有使用者親自明確確認後，才可合併 `main`。

## Testing Decisions

- 優先測可觀察的結果、儲存與交換語意，不以某個控制項或內部函式的存在當作成功。沿用應用／持久化整合、幾何契約、JSON 往返及薄 WinForms 接線四個現有測試縫，不為每個按鈕另建抽象層。
- 導覽與畫布測試覆蓋排序／篩選後上下鍵、文字欄位焦點、搜尋時保留原圖、快速切圖與取消舊圖載入、兩頁共用視角、F 與倍率更新，以及不同倍率／視窗尺寸下兩軸平移邊界。
- 標註工具測試覆蓋 CLA／OBD／SEG 可見工具、進入時選取模式、新標註集自動切換、Ctrl+A 範圍、選取模式 Ctrl+點擊、未完成形狀切頁捨棄、共同寬度 1／15／100 與預覽／提交結果對照。
- 顯示測試覆蓋透明度 0／40／100%、OBD 填色、SEG 筆刷與線型、外框／文字／控制點可見性，以及切換標註集與重開專案重設。JSON 結構不新增透明度欄位。
- 數量測試覆蓋新增、刪除、同類別聯集、橡皮擦分裂、匯入、Undo/Redo、切換標註集和空圖；10,000 張清單不得因逐列資料查詢而退化。
- 幾何測試覆蓋最近點位於邊段中途、凹形外圈、多個空洞阻擋、等距決策、整數座標、洞面積與 Non-Zero 填色，以及未修改匯入路徑逐點一致。
- 效能從完成輸入到標註持久化並顯示的時間逐筆量測，不只測旋轉 FPS；包含現有 SEG 素材、17,000 點、重疊聯集、空洞生成、連續操作、處理中連按切圖、錯誤後資料一致性與記憶體穩定性。任一驗收案例超過 1 秒或 UI 無回應即視為未通過，不以 CI 綠燈代替本機驗收。
- Release x64 建置、非互動測試及匿名 ZIP 由現有 CI 執行；目前電腦做實際鍵鼠、效能和 1920×1080 版面驗收，另覆蓋 1366×768、100%～200% DPI 的可操作性。

## Out of Scope

- 模仿附圖中的模型、訓練、自動標記、流程圖及其他未列出的功能。
- 改變 CLA／OBD／SEG JSON 交換格式、未修改匯入路徑的點序，或改寫既有完整資料集。
- 把透明度保存進專案或 JSON，及為每個 SEG 工具保留獨立線寬。
- 對未納入本次素材與壓力案例的任意複雜幾何宣稱已證明 1 秒上限。
- GitHub 儲存庫私有化、重寫歷史或清除既有資料集；這些仍屬另案。
- 在使用者親自確認前合併 Draft PR。

## Further Notes

- 本規格補充第一版正式規格與既有 SEG 幾何 ADR；現有資料集、自動切分、備份與 JSON 相容規則持續適用。
- 現有畫筆／筆刷完成事件會同步進入幾何與儲存路徑；反覆讀取和聯集是待量測的瓶頸線索，尚非已證實的唯一原因。
- GitHub Issue #1 保存第一版完整規格；本次增量規格作為獨立工作項目追蹤。
