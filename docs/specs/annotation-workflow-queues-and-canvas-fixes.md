# 標註工作流程、專案工作佇列與畫布互動增量規格

## Problem Statement

使用者在 SEG 標註時，按住 Ctrl 切換為擦除效果後仍會出現明顯卡頓；線形工具的預覽端點與實際圓頭結果也不一致。標註工具游標在圖片外仍被限制在圖片邊界，右上導覽縮圖又可能遮住繪製路徑，使游標回饋、實際滑鼠位置與提交幾何彼此不一致。

既有匯入佇列的卡片寬度、長文字與進度呈現不足，標註 JSON 只能建立新標註集，無法先預覽並選擇如何匯入目前標註集。匯出仍是停用整個主視窗的單次操作，使用者不能排隊、查看進度、取消或回查結果。標註集刪除缺少清楚的名稱不符回饋，透明度可輸入任意百分比，資料集控制項與主選單排列也未符合新的操作需求。

## Solution

改善實際畫布重繪路徑，使全部五種 Ctrl 擦除工具在既有高複雜度素材上達到可量測的 60 FPS 目標；讓線形預覽使用與實際標註相同的圓頭。畫布依實體滑鼠位置切換一般游標與標註游標，提交幾何仍限制在圖片內；標註手勢進行期間隱藏導覽縮圖，完成或取消後恢復。

將匯入與匯出提升為同一專案工作佇列中的工作，使用單一 FIFO 依加入順序執行，以固定寬度的垂直卡片視窗顯示真實或不確定進度、取消、結果、警告與詳細錯誤。標註 JSON 在排隊前完整預檢並顯示設定視窗，讓使用者分別選擇標註／類別與資料集狀態的匯入模式，再以單一不可復原交易修改加入時固定的目前標註集。匯出使用暫存檔安全發布，提供排隊、取消、唯一輸出名稱與結果導覽。

同時收緊標註集刪除確認、透明度階距、資料集控制項並排契約及主選單分組，並以 Release x64、自動測試、實機效能、Visual Studio Designer、Windows 操作及 100%／150%／200% DPI 作為分開的交付門檻。

## User Stories

1. 身為 SEG 使用者，我希望按住 Ctrl 時仍能流暢移動與繪製，以便不用在新增與擦除之間承受不同的操作延遲。
2. 身為 SEG 使用者，我希望矩形、圓形、多邊形、筆刷與線形的 Ctrl 擦除都達到相同效能門檻，以便工具切換不改變流暢度。
3. 身為 SEG 使用者，我希望獨立橡皮擦也被納入效能對照，以便共用瓶頸不會只修正 Ctrl 路徑。
4. 身為效能驗收者，我希望一般模式與 Ctrl 模式使用同一素材與滑鼠路徑量測，以便比較結果可信。
5. 身為效能驗收者，我希望平均、尾端延遲與單幀停頓都有門檻，以便平均 FPS 不會掩蓋肉眼可見卡頓。
6. 身為線形工具使用者，我希望尚未完成的線段兩端為圓頭，以便預覽與實際標註結果一致。
7. 身為線形工具使用者，我希望不同筆寬、縮放及 Ctrl 狀態都維持圓頭，以便預覽契約不受顯示條件影響。
8. 身為標註使用者，我希望滑鼠位於圖片外但仍在畫布時顯示一般箭頭，以便游標忠實反映實體位置。
9. 身為標註使用者，我希望在圖片外按下左鍵仍能從最近的圖片邊界開始標註，以便不必精確移回圖片內才可繼續工作。
10. 身為標註使用者，我希望移出圖片後的預覽與提交幾何仍限制在圖片內，以便不會保存越界標註。
11. 身為 OBD 使用者，我希望矩形工具遵守相同的圖片外游標與邊界規則，以便 OBD 與 SEG 操作一致。
12. 身為 SEG 使用者，我希望全部繪製與擦除工具遵守相同的圖片外游標與邊界規則，以便不同工具沒有例外。
13. 身為標註使用者，我希望開始一筆標註後暫時隱藏右上導覽縮圖與收合按鈕，以便繪製路徑不會穿過縮圖互動區。
14. 身為線形工具使用者，我希望縮圖從第一點到第二點完成前持續隱藏，以便兩次點擊之間不會重新遮住畫布。
15. 身為多邊形工具使用者，我希望縮圖從第一點到閉合或取消前持續隱藏，以便多段手勢完整一致。
16. 身為標註使用者，我希望完成、按 Esc、切換工具、切圖、切標註集或切頁造成取消時恢復縮圖，以便縮圖不會永久消失。
17. 身為標註使用者，我希望沒有進行中手勢時，滑鼠進入縮圖顯示一般箭頭並可操作導覽功能，以便縮圖仍是正常的視野工具。
18. 身為大量工作使用者，我希望匯入與匯出出現在同一工作佇列，以便跨類型順序只有一種解讀。
19. 身為使用者，我希望工作依全域加入順序一次執行一項，以便匯出看到前序匯入完成後的一致專案狀態。
20. 身為使用者，我希望等待中與執行中的工作合計最多十筆，以便連續點擊不會建立無界工作量。
21. 身為使用者，我希望最近五十筆已完成、完成但有警告、失敗或取消工作保留在本次專案工作階段，以便回查近期結果。
22. 身為使用者，我希望工作歷史不跨程式重啟保存，以便佇列不需要處理過期來源與輸出路徑。
23. 身為使用者，我希望第一筆工作加入時自動顯示工作佇列，關閉視窗後也能由選單重新開啟，以便工作持續執行且隨時可查。
24. 身為使用者，我希望工作佇列固定為適合垂直卡片的 DPI 感知寬度且高度可調，以便不需要橫向捲動。
25. 身為使用者，我希望每張卡片顯示工作方向、類型、來源、目標、狀態、進度、摘要及適用操作，以便快速理解混合佇列。
26. 身為使用者，我希望來源路徑單行省略並可查看全文，以便固定寬度下仍能辨識來源。
27. 身為使用者，我希望詳細錯誤可換行、限制高度、垂直捲動及複製，以便長錯誤不撐壞卡片又可供診斷。
28. 身為使用者，我希望總量未知的掃描、驗證與原子寫入顯示跑馬燈，以便進度條不偽造百分比。
29. 身為使用者，我希望已知總量的圖片匯入與 ZIP 匯出顯示真實處理數與百分比，以便掌握完成程度。
30. 身為使用者，我希望失敗或取消卡片保留最後進度並顯示原因，以便了解停止位置。
31. 身為標註管理使用者，我希望沒有選取標註集時停用標註 JSON 匯入，以便不會建立沒有目標的工作。
32. 身為標註管理使用者，我希望 JSON 工作在加入時固定目前標註集 ID、名稱與型別，以便等待期間切換畫面不會改變匯入目標。
33. 身為標註管理使用者，我希望選擇 JSON 後先看見型別、類別、圖片數與資料集狀態摘要，以便在修改資料前了解來源。
34. 身為標註管理使用者，我希望設定前完整預檢格式、版本、類別、圖片對應、尺寸、幾何及未知欄位，以便錯誤盡早被發現。
35. 身為標註管理使用者，我希望工作執行時重新讀取並驗證 JSON，以便等待期間來源變更不會被當成原先內容。
36. 身為標註管理使用者，我希望 JSON 型別與目前標註集不同時立即被拒絕並留下失敗卡片，以便 CLA、OBD、SEG 不會混入錯誤標註集。
37. 身為標註管理使用者，我希望其他預檢失敗也留下不占活動名額的失敗卡片，以便錯誤仍可在工作歷史中回查。
38. 身為標註管理使用者，我希望未知欄位清單與風險在設定視窗中可見，並由我主動同意忽略後才能繼續，以便不會靜默接受新版或拼錯欄位。
39. 身為標註管理使用者，我希望標註／類別與資料集狀態可以分別勾選及選擇模式，以便每次匯入只修改需要的資料。
40. 身為標註管理使用者，我希望至少選擇一組匯入內容後才能加入佇列，以便避免空工作。
41. 身為標註管理使用者，我希望 CLA 可選擇只加入空白圖片或取代所有對應圖片，以便維持一張圖片最多一個 CLA 類別。
42. 身為 OBD／SEG 使用者，我希望可選擇只加入空白圖片、加入所有圖片或取代所有對應圖片，以便支援補入、追加與同步三種用途。
43. 身為標註管理使用者，我希望「只加入空白圖片」逐張依目前標註集是否已有標註判定，以便不覆寫已有成果。
44. 身為 OBD／SEG 使用者，我希望「加入所有圖片」保留既有物件並把 JSON 物件追加到最上層，以便新增資料不改寫原有物件。
45. 身為 SEG 使用者，我希望匯入追加時不因同類別重疊而自動聯集，以便交換資料幾何保持原樣。
46. 身為標註管理使用者，我希望「取代所有對應圖片」只處理 JSON 列出的圖片，以便未出現在來源中的專案圖片保持不變。
47. 身為標註管理使用者，我希望取代模式能用 JSON 空標註清空對應圖片，以便 JSON 可明確表達空白結果。
48. 身為標註管理使用者，我希望 JSON 的全部類別定義都被匯入，以便即使目前沒有實例也能保留類別結構。
49. 身為標註管理使用者，我希望同名類別不論 JSON 顏色如何都沿用目前標註集的類別與顏色，以便匯入不會暗中改色。

## Implementation Decisions

- Ctrl 擦除效能涵蓋 SEG 矩形、圓形、多邊形、筆刷及線形，獨立橡皮擦作為共因對照。先分段量測畫布事件、裁切、既有標註繪製、游標與預覽重繪，不預設瓶頸是幾何差集，因為差集只在完成時提交。
- 效能門檻使用約 17,000 點壓力素材與相同滑鼠路徑。一般與 Ctrl 模式平均至少 60 FPS，第 95 百分位單幀不超過 33.3ms，且不得出現超過 100ms 的單幀停頓。
- 線形尚未完成的預覽筆畫使用圓形起點、終點及連接，並與實際 Round 端點幾何、筆寬、縮放、Ctrl 新增／擦除及邊界裁切一致。
- 標註工具是否顯示由實體滑鼠是否位於目前圖片畫面範圍決定；圖片外顯示系統箭頭。標註座標仍投影到最近合法圖片邊界，所有提交維持既有圖片內不變條件。
- OBD 矩形及全部 SEG 繪製／擦除工具套用圖片外游標規則；OBD／SEG 選取工具維持既有命中、框選與拖曳規則。
- 導覽縮圖在任何標註手勢正式開始後連同收合按鈕隱藏，直到完成或取消。矩形、圓形、筆刷與橡皮擦以按下至放開為手勢；線形以第一點至第二點為手勢；多邊形以第一點至閉合或取消為手勢。所有取消與頁面／目標切換路徑都必須恢復縮圖。
- 沒有進行中標註手勢時，縮圖與收合按鈕優先於標註工具接收命中，使用一般箭頭並維持既有導覽操作。是否在適合視窗時顯示縮圖維持現況，不在本次修改。
- 匯入與匯出都是專案工作，共用一個專案工作佇列與單一 FIFO 執行器。介面只有一個工作佇列視窗，不建立分開的匯入／匯出視窗。
- 工作狀態包含等待中、執行中、已完成、完成但有警告、失敗與已取消。等待中與執行中合計上限十筆；終止歷史合計保留最近五十筆。預檢失敗可直接建立失敗歷史，但不占活動工作名額。
- 佇列、工作與歷史只存在目前專案的本次程式工作階段，不寫入專案資料庫或應用程式設定，也不在重啟後恢復。
- 工作佇列視窗固定 DPI 感知寬度但允許調整高度。卡片填滿內容寬度，容器只允許垂直捲動。來源使用單行省略及完整 ToolTip；錯誤詳細資料換行、限制高度、垂直捲動且可複製。
- 每張卡片都有進度條。等待顯示零；未知總量使用不確定模式；總量確定後顯示真實比例；完成顯示 100%；失敗或取消保留最後已知進度。
- 標註 JSON 匯入入口只有在專案及目前標註集都存在時啟用。工作要求在加入時保存目標標註集不可變 ID、當時名稱、型別、來源路徑、未知欄位同意及匯入模式；後續 UI 選取不改變目標。
- 選擇 JSON 後先在背景完整預檢格式、版本、型別、類別、圖片唯一對應、尺寸、幾何與未知欄位，再顯示設定摘要。執行時重新讀取來源並完整驗證；不保存來源內容快照。
- 預檢型別不符或其他致命錯誤時不顯示可執行設定，也不排入等待列；直接建立失敗卡片，記錄來源、目標及原因。
- 未知欄位在設定視窗完整列出。「忽略未知欄位並繼續」預設未勾選；未同意時不能建立工作。執行時若來源出現預檢時未同意的新未知欄位，工作失敗。
- 設定視窗將「標註與類別」及「資料集狀態」分成兩個獨立核取選項，至少選擇一組才可匯入。Retest 不出現在匯入選項且永遠不由 JSON 修改。
- CLA 的標註模式只有「只加入空白圖片」與「取代所有對應圖片」。OBD／SEG 再提供「加入所有圖片」。空白圖片以目標標註集中該圖片目前是否沒有任何對應標註判定。
- 「只加入空白圖片」只匯入 JSON 中具有非空標註且目標目前空白的圖片；JSON 空標註不清除資料。
- OBD／SEG「加入所有圖片」保留既有物件與順序，JSON 物件依來源順序取得新 ID 並追加到最上層。匯入不觸發同類別 SEG 聯集。
- 「取代所有對應圖片」只作用於 JSON data 中列出的專案圖片。先移除該圖片在目標標註集的既有標註，再依 JSON 建立結果；JSON 空標註明確清空該圖片。未列出的圖片不變。
- 勾選「標註與類別」時匯入 JSON classes 的全部類別定義。同名比對區分大小寫；同名類別不論顏色都沿用目標既有類別與顏色；不存在的類別使用 JSON 顏色建立。
- 資料集狀態模式為「只加入未分配圖片」與「取代所有對應圖片」。前者只更新目標目前為未分配的 JSON 對應圖片；後者依 JSON 將對應圖片設為 train、test、not_used 或未分配。未列出的圖片與全部 Retest 不變。
- 匯入既有標註集的 JSON 不建立 Undo/Redo。加入佇列前必須顯示無法復原警告並取得再次確認；取消不建立工作或失敗卡片。成功或失敗仍使用單一資料庫交易，禁止部分修改。
- 匯出工作類型為目前標註集 JSON、所選圖片 ZIP 及全部圖片 ZIP。輸出路徑與目標識別在加入時固定；JSON 內容及全部圖片範圍在執行開始時讀取；所選圖片 ID 在加入時固定。
- 等待中的匯出可立即取消。圖片 ZIP 在安全檢查點回應取消；JSON 若在不可中斷序列化步驟中可延後結束，但取消後不得發布最終檔。
- 所有匯出寫入輸出目錄中的暫存檔，只有完整成功才發布最終檔；取消與失敗清除暫存。路徑衝突時沿用唯一名稱規則，永不覆寫既有檔案。
- 圖片 ZIP 略過缺失圖片並以完成但有警告記錄成功與缺失數。沒有任何可匯出圖片時失敗且不發布空 ZIP。
- 匯出完成卡片保存實際輸出路徑，提供開啟所在資料夾並選取檔案的操作。檔案不存在時按鈕停用並顯示原因，不直接使用預設程式開啟輸出檔。
- 有等待或執行工作時，禁止新增、開啟、另存、備份還原、缺失圖片修復、刪除圖片及刪除／重新命名標註集等會使工作目標失效的命令；診斷、工作佇列、瀏覽及安全的一般操作維持可用。
- 圖片／資料夾匯入與圖片 ZIP 匯出執行時仍可編輯既有標註。JSON 匯入或匯出執行時只鎖定其目標標註集的標註、類別與資料集變更，其他標註集維持可用。
- 關閉應用程式時顯示等待中與執行中匯入／匯出數量。確認關閉後取消等待工作、要求取消執行中的可取消工作、清除匯出暫存檔，並等待不可中斷 JSON 交易安全結束；取消關閉時所有工作維持原狀。
- 標註集刪除仍以目前選取標註集 ID 為唯一目標，輸入文字只驗證該目標目前名稱。名稱不符時不刪除任何標註集，並顯示包含目前目標名稱的警告。先以真實 UI 路徑重現現況，再依證據修正 UI 或選取同步，不預設儲存層錯誤。
- 標註透明度值域為 0、10、20 至 100。滑桿、方向鍵、滾輪及數字輸入都正規化為十倍數；非十倍數四捨五入到最近的十倍數。標註集切換仍重設為 40%。
- 透明度 0% 時，封閉 OBD／SEG 的填色透明而既有類別色輪廓、文字與選取提示維持。未選取 SEG 筆刷、線形及單點筆畫可完全消失；不新增外框幾何。
- 資料集隨機切分區使用兩欄版面：Train／Test 比例並排，切分所選／切分全部並排，各占 50%。在支援的 DPI 與 1366×768 下不得自動改成上下排列，左側清單仍須有非零可用寬度。
- 主選單固定為專案、工作、管理、說明。專案只保留新增、開啟、儲存、另存新檔；工作提供開啟工作佇列；管理包含缺失圖片、備份與診斷資訊；說明保留快捷鍵。
- 不新增工作佇列資料庫結構。專案資料庫只因使用者選擇的 JSON 匯入模式修改既有標註、類別及資料集狀態。
- 工作分支為 `annotation-workflow-queues-and-canvas-fixes`，從最新 main 建立。先提交規格、計畫、領域詞彙與 ADR，再依可獨立審查的功能邊界提交。只有使用者完成桌面驗收並再次明確批准後才能合併 main。

## Testing Decisions

- 好的測試驗證可觀察的工作順序、狀態、進度、專案資料、輸出檔、畫布像素、游標狀態、提交幾何與控制項版面，而不是鎖定私有方法名稱或為每個內部步驟建立接口。
- 優先沿用四個最高既有測試縫：專案儲存／工作階段整合、畫布與主視窗互動、WinForms 版面、SEG 幾何與效能素材。只新增一個最高層的專案工作佇列生命週期接縫，接受不可變工作描述並發布狀態快照。
- 專案工作佇列測試覆蓋混合匯入／匯出 FIFO、任何時刻單一執行、十筆活動上限、五十筆終止歷史、直接失敗紀錄不占活動名額、非致命續跑、致命停止、等待取消、執行取消、精準命令鎖、專案替換防護及關閉協調。
- 工作卡片測試覆蓋固定寬度、無橫向捲軸、DPI 縮放、長路徑、錯誤展開／複製、真實／不確定進度、完成但有警告、結果檔不存在及單一 modeless 視窗。
- JSON 匯入測試以專案儲存整合層驗證加入時固定目標、執行時來源漂移、CLA／OBD／SEG 型別矩陣、三種標註模式、兩種資料集模式、全類別匯入、同名不同色、新類別、JSON 空標註、未列出圖片不變、Retest 不變、未知欄位、圖片名稱／尺寸／幾何錯誤、單一交易與無 Undo/Redo。
- JSON 設定視窗測試驗證沒有選取標註集時入口停用、預覽摘要、模式依型別變化、至少一組選取、未知欄位同意、無法復原二次確認、取消不建立工作，以及型別不符形成失敗卡片。
- 匯出測試覆蓋 JSON、所選 ZIP、全部 ZIP、前序匯入可見性、所選 ID 固定、執行時全部範圍、逐檔進度、取消暫存清理、不可中斷 JSON 取消、輸出撞名、缺失圖片部分成功、零可用圖片失敗及實際輸出路徑。
- 畫布測試必須驅動真正的 ImageCanvasControl 滑鼠與鍵盤事件。覆蓋圖片內外、四邊與四角、不同縮放、OBD 與全部 SEG 繪製工具、一般箭頭、邊界提交、縮圖命中優先，以及手勢完成／Esc／切圖／切頁／切工具後縮圖恢復。
- 線形預覽使用像素或可觀察幾何驗證圓頭，不只檢查 Pen 屬性；涵蓋至少三種筆寬、縮放、Ctrl 新增／擦除與圖片邊界。
- 效能測試在 Release x64、固定控制項尺寸與素材下暖機後收集每幀原始時間。五種工具一般／Ctrl 路徑分別驗證平均 60 FPS、95 百分位 33.3ms 及 100ms 最大停頓門檻；獨立橡皮擦作共因對照。Hosted CI 不宣稱通過指定 Windows 電腦的實機 FPS。
- 透明度測試覆蓋滑桿、數字、方向鍵與非十倍數正規化，並以畫面像素驗證 0%、40%、100% 下封閉形狀輪廓／填色及筆刷／線形既定行為。
- 資料集版面測試驗證兩組 50% 欄位、文字完整、控制項 containment、Tab 順序及左側清單非零寬度；在 1366×768、100%、150%、200% DPI 另做 Windows 實機驗收。
- 刪除測試同時涵蓋選取 A 輸入 A、選取 A 輸入現有 B、大小寫不同、重名標註集、取消與刪除後選取刷新；只允許正確目標及名稱組合刪除。
- 選單測試驗證四個頂層選單及精確子項，並確認 Designer 可開啟受影響 Form／UserControl、固定控制項事件沒有重複接線。
- 執行 Release x64 建置、所有非互動測試、手動效能測試與 GitHub Actions。Visual Studio Designer、Windows 真實滑鼠手感、工作取消、檔案總管導覽及 DPI 各自保留獨立驗收證據。

## Out of Scope

- 改變導覽縮圖在適合視窗、浮點捨入或無可平移範圍時的既有顯示方案。
- 讓 OBD／SEG 選取工具在圖片外建立或移動標註，或改變既有命中、框選與拖曳語意。
- 將工作平行執行、重新排序、暫停、重試、排程到未來時間或移到其他專案。
- 持久化工作佇列、工作歷史、等待工作或中斷點，或在重啟後恢復工作。
- 匯入多份標註 JSON 作為同一工作，或在一個設定視窗逐張圖片自訂模式。
- 從 JSON 匯入 Retest、變更 JSON 交換版本或猜測未知欄位語意。
- 為匯入既有標註集建立 Undo/Redo；所有此類匯入都以不可復原警告與原子交易保護。
- 直接開啟匯出 JSON／ZIP、覆寫既有輸出檔，或保留取消／失敗的部分輸出。
- 為 0% 的 SEG 筆刷、線形或單點筆畫新增外圍輪廓幾何。
- 改變透明度預設 40%、標註顯示開關、資料集切分演算法、最低 test 數或每類 train 保留規則。
- 在使用者完成 Designer、Windows、DPI、效能與工作流程驗收並明確批准前合併 main。

## Further Notes

- 本規格補充既有標註介面、SEG 效能、畫布互動與匯入工作流程規格；衝突處以本規格為準，未提及的幾何、圖片、資料庫、JSON 與 Undo/Redo 契約持續適用。
- 「資料集」在本規格只指 train、test、未分配與 not_used 狀態；JSON 匯入目標使用正式詞彙「目前標註集」，不得混用。
- 專案工作、匯出工作與專案工作佇列是新增／修訂的正式領域詞彙；混合匯入與匯出共用單一 FIFO 的理由由新 ADR 記錄。
- 參考畫面只用來確認匯入前預覽及獨立匯入選項，不導入其中未經確認的頁籤、格式選單、ROI、Mask 或 Guide 功能。
- 文件、工作佇列核心、JSON 匯入、匯出、佇列 UI、畫布效能／游標、其餘 UI 修正及驗收證據應拆成可獨立審查的提交。
