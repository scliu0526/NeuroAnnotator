# Neurocle 分階段實作計畫

標註介面、SEG 完成效能與空洞橋接的後續修改另依[增量實行計畫](annotation-ui-seg-performance.md)執行；本文件保留第一版的階段規劃。

標註介面、Ctrl 擦除、匯入佇列、資料集右欄與類別列的後續修改另依[標註介面與匯入工作流程增量計畫](annotation-ui-workflow-refresh.md)執行。

## 執行原則

- 每一階段依序完成「實作 → 自動測試 → 指定電腦驗收 → 缺陷修正」後，才進入下一階段。
- 不以日曆日期作承諾；完成條件是驗收證據成立且沒有已知可重現的功能性缺陷。純外觀問題可記錄後延。
- 先建立可測試的領域與應用用例，再接 WinForms；避免把規則埋在事件處理器。
- 只實作正式規格已有的功能，不預先加入訓練、外掛、雲端或其他推測性擴充。

## Phase 0：基線、建置與發佈骨架

### 交付

- 建立 .NET Framework 4.7.2、x64 WinForms 方案、領域／應用／基礎設施／UI 與測試專案。
- 建立套件授權清單、資源檔及繁體中文基本字串。
- 建立 GitHub Actions `windows-2022` 的還原、x64 建置、非 UI 測試與可攜式 ZIP 產出。
- 建立最小啟動程式、全域錯誤邊界與版本資訊。

### 驗證閘門

- 全新 checkout 可在 CI 建置並執行測試。
- ZIP 在斷網的指定電腦解壓後可啟動，且原生 SQLite 元件可載入。
- 100%～200% 指定 DPI 啟動不截斷最小畫面。

## Phase 1：SEG 幾何風險原型

### 交付

- 建立可拋棄的 Clipper2 幾何核心原型，不接正式 UI。
- 解析參考 SEG JSON，覆蓋矩形、橢圓、筆刷、封閉畫筆、線型、旋轉、局部擦除、自交與多次繞行。
- 實作 Non-Zero 填色、聯集、差集、洞橋接、筆刷膨脹、變形、邊界限制與完成時四捨五入。
- 建立 17,000 點與大量 Undo 快照的效能／記憶體量測。

### 驗證閘門

- `test-and-acceptance-plan.md` 的 SEG-PROTOTYPE 全部通過。
- 一般拖曳／旋轉預覽在指定電腦達 30 FPS。
- 若任何核心語意無法穩定達成，停止正式 SEG 開發並新增 ADR 重新決策。

## Phase 2：專案、SQLite 與圖片匯入

### 交付

- 建立資料模型、結構版本、交易工作單元、專案鎖、混合式儲存、另存新檔。
- 建立受管理圖片目錄、不可變 ID、連續序號、SHA-256、格式與大小驗證。
- 完成多檔／資料夾匯入、遞迴詢問、撞名、部分成功、取消與進度報告。
- 完成缺失圖片偵測、相同雜湊重新連結、永久移除。
- 完成每日及遷移前資料庫備份、最近五份管理、還原與損毀提示。

### 驗證閘門

- SQLite 交易、取消、崩潰模擬、專案鎖、缺失檔與備份還原自動測試通過。
- 100 MB、10,000×10,000、100M 像素與 10,000 張邊界值行為符合規格。
- 匯入失敗不回滾已完成的有效圖片，且報告可追溯每一失敗原因。

## Phase 3：圖片清單、預覽與畫布基礎

### 交付

- 虛擬化文字清單、序號／檔名排序、搜尋、篩選及圖片預覽。
- 四頁導覽、適合視窗與固定／連續倍率、滾輪與 Space 平移。
- 圖片解碼生命週期與快取上限，避免長時間瀏覽累積記憶體。

### 驗證閘門

- 10,000 筆清單 10 秒內可互動；5K 圖切換 2 秒內完成。
- 連續瀏覽 100 張圖片沒有持續性記憶體成長。
- 各縮放與平移輸入在 100%～200% DPI 手動驗收通過。

## Phase 4：標註集、類別與 CLA

### 交付

- 標註集建立、切換、重新命名、輸入全名刪除，以及類別 CRUD、顏色與級聯刪除。
- 新標註集 `class1` 與至少一類別不變條件。
- CLA 單類別指定、取代、清除及跨圖片瀏覽。
- 每標註集 Undo/Redo 基礎、100 動作／512 MiB 淘汰與自動儲存。

### 驗證閘門

- 同名標註集仍以內部 ID 隔離；切換不串資料。
- 類別刪除、Undo/Redo、關閉後清空歷史、永久刪除例外符合規格。

## Phase 5：OBD

### 交付

- 矩形建立、選取、移動、八控制點縮放、改類別、多選、層級與邊界限制。
- 透明填色、外框及類別名稱顯示。

### 驗證閘門

- 物件不越界；多選移動與主物件縮放語意正確。
- 暫時置頂、無修改復原及編輯後永久置頂皆有自動領域測試與 UI 冒煙測試。

## Phase 6：正式 SEG

### 交付

- 將 Phase 1 驗證過的幾何契約移入正式核心。
- 完成全部建立工具、透明度、選取／多選、變形、層級、同類別新繪製聯集與局部橡皮擦。
- 完成洞、分裂、自交與未修改原始路徑保存。

### 驗證閘門

- 所有提供的 SEG JSON 樣本通過語意回歸。
- 不同類別重疊、同類別合併例外、擦除碎片及洞可視與匯出一致。
- 指定電腦一般互動維持至少 30 FPS，Undo 記憶體限制確實生效。

## Phase 7：資料集分配與 Retest

### 交付

- 四種資料集狀態、批次指派／清除、Retest 設定／清除與右鍵選單。
- 80/20 連動輸入與每次重新隨機的多標籤分層切分。
- 約束優先順序、不可滿足警告與缺失圖片處理。

### 驗證閘門

- 可行資料集滿足每類 train 10 張、整體 test 3 張，再檢查比例與平衡。
- 不可行資料集只警告、不阻止；Retest 不被自動切分改動。
- 空標註負樣本與 CLA 空類別的分配行為符合規格。

## Phase 8：JSON 交換與圖片 ZIP

### 交付

- 嚴格且原子的 JSON 匯入、未知欄位警告、單標註集 JSON 匯出。
- 選取／全部圖片 ZIP 匯出、根目錄扁平結構及輸出撞名後綴。
- UTC 時間、版本、set 映射、空標註、Retest、固定 rotation 及缺失圖片規則。

### 驗證閘門

- CLA、OBD、全部 SEG 樣本通過 golden file 結構檢查與語意 round-trip。
- 任何 JSON 致命錯誤均零寫入；未知欄位只有使用者繼續時才匯入。
- 「全部圖片」不受清單篩選影響；ZIP 內內容雜湊與專案圖片相同。

## Phase 9：可用性、日誌與最終驗收

### 交付

- 每日日誌、永久保留、占用空間顯示與開啟資料夾。
- 鍵盤快捷鍵、錯誤訊息、取消流程、DPI 修正及可攜式發佈整理。
- 使用小型合成／匿名素材建立可重跑的驗收包。

### 驗證閘門

- 完整離線端對端流程：建立專案、匯入、三型標註、切分、重開、JSON 匯出、圖片 ZIP、備份還原。
- 所有自動測試與手動矩陣通過，且無已知可重現的功能性缺陷。
- 發佈 ZIP 在指定電腦與支援的 Windows/DPI 組合完成驗收。

## 後續但不在本計畫內

- 訓練、推論與自動標記另立規格，不在第一版預留未經驗證的框架。
- GitHub 私有化與歷史資料集清除是獨立的高風險維護流程，須先完成可驗證備份並另行授權。
