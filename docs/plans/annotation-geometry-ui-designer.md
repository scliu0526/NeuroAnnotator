# 標註幾何、介面與 Designer 實行計畫

## 範圍與完成條件

- 以[增量正式規格](../specs/annotation-geometry-ui-designer.md)與 [ADR-0005](../adr/0005-seg-hole-bridge-network.md) 為驗收契約。
- 工作分支為 `annotation-geometry-ui-designer`，從已包含 `annotation-canvas-interactions` 的最新 `main` 建立。
- 圖示資源納入專案；新增標註集參考畫面保留在本機供對照，不納入提交。
- 自動測試、Release x64 建置、CI、Visual Studio Designer 驗收與 Windows/DPI 桌面驗收分別紀錄。Draft PR 保持未合併，直到使用者另行明確指示。

## 1. 建立基線與回歸樣本

1. 記錄分支、工作樹、Release x64 建置與全部測試基線；現有失敗與本次變更分開。
2. 以既有單洞、凹形外圈、阻擋洞、17,000 點路徑及未修改匯入路徑為幾何基線；增加兩洞及三洞以上樣本。
3. 重現上下鍵需按兩次、畫筆放開左鍵後預覽停住、框選填色、起點色彩與大小的現況，保留可對照的渲染與鍵盤案例。

**驗證：** 每個缺口都有可穩定重現的外部行為，且未先假定原因。

## 2. 實作空洞橋接網路

1. 將輪廓間最短合法連線整理為可供外圈與任意兩個空洞使用的候選，沿用現有整數邊上端點、阻擋與合法性檢查。
2. 以候選線建立可連通外圈與所有空洞的最小生成樹；等距時優先既有合法邊，再用座標序確保穩定。
3. 將樹狀橋接編碼回單一 `PolyGon` 路徑，每條橋接往返重合，洞維持相反繞行，不改變填色面積。
4. 幾何修改後重算網路；未修改匯入路徑沿用原序。無合法連通樹時返回可辨識失敗，讓上層取消修改、提示使用者且不建立歷史。
5. 先量測單洞與多洞候選數量及各階段耗時；只對實際熱點做必要的剪枝與快取。

**驗證：** 兩洞分接／串接、多洞最小生成樹、等距、凹形、阻擋、無法連通、Non-Zero 遮罩、面積、JSON 往返與舊路徑逐點一致通過；單洞 1 秒、多洞 2 秒目標達成。

## 3. 建立可互動縮圖

1. 在畫布視角層建立縮圖映射，由原圖矩形、畫布可見矩形與目前視角計算縮圖尺寸和視野框。
2. 圖片超出畫布時才顯示右上角縮圖；保持長寬比、限制最大 180×120 畫面像素並依 DPI 調整。
3. 將縮圖點擊與視野框拖曳轉為既有視角平移，沿用捲軸與右鍵拖曳的邊界。縮圖事件由縮圖消化，不誤傳給標註畫布。
4. 加入收合／展開圖示，在本次執行期間共用狀態。圖片放得下時隱藏縮圖與圖示；再次超出時恢復之前狀態。

**驗證：** 圖片頁與標註頁、橫圖與直圖、單軸／雙軸超出、縮放、捲軸、點擊、拖曳、收合、切圖、切集與重開行為符合規格。

## 4. 改善選取、畫筆與鍵盤互動

1. 將 OBD／SEG 框選預覽改為無填色 2px 黑色虛線，不變更框選命中與完成後選取樣式。
2. 繪製畫筆起點的平常與可閉環兩種狀態，讓判定半徑、顯示大小與點擊完成行為使用同一畫面座標語意。
3. 重新整理畫筆手勢狀態：左鍵放開不凍結末端預覽；再按繼續加點；起點點擊閉環；取消路徑清除所有未提交狀態。
4. 追蹤方向鍵按下、鍵盤連發與放開的操作群組。有 OBD／SEG 選取時群組移動 1px，共用邊界檢查，放開後建立單一完成操作；無選取時上下鍵立即切圖。
5. 於主視窗非文字輸入情境接線工具鍵，先取消未完成預覽再切換。依 CLA／OBD／SEG 支援矩陣接受或忽略按鍵。

**驗證：** 渲染像素、滑鼠手勢、單次鍵、鍵盤連發、多選、越界、Undo/Redo、切圖、文字焦點、工具支援矩陣與未完成預覽取消均有畫布或主視窗回歸測試。

## 5. 更新工具、類別與新增標註集

1. 將工具圖示與標註集類型圖示納入 WinForms 嵌入式資源，依按鈕大小等比縮放，不在執行時讀取專案相對路徑。
2. 統一工具提示的中文名稱與快捷鍵，移除 OBD／SEG 前綴，並讓快捷鍵說明視窗與實際接線同步。
3. 將新增類別改為無對話框命令，掃描完全匹配的 `classN` 名稱，建立下一個編號並保留既有改名功能。
4. 依參考畫面將新增標註集改為三張類型卡片與名稱輸入；只保留 CLA、OBD、SEG，不新增描述資料契約。
5. 以明確的選取視覺、鍵盤焦點順序、Accept/Cancel 行為與建立按鈕啟用條件完成對話框。

**驗證：** 圖示完整性、工具名稱與鍵位、CLA／OBD／SEG 可見工具、類別編號邊界、三張類型卡片、名稱空白與建立結果通過。

## 6. 將可見視窗搬至 Designer

1. 依視窗與 UserControl 逐一分離穩定的控制項建立、屬性及版面設定，與執行期資料繫結、事件命令及自繪邏輯分開。
2. 每搬移一個畫面就建置、執行原互動測試，並核對控制項名稱、可見性、Dock/Anchor、TabIndex、Accept/Cancel 按鈕與事件只接線一次。
3. 主視窗依版面區塊分階段搬移，保留現有 z-order、選單／狀態列與填滿頁面的排列契約。
4. 自繪畫布在 Designer 中只顯示控制項邊界與靜態屬性，不在設計時載入專案、圖片、資料庫或動態標註。

**驗證：** Visual Studio 可逐一開啟全部 Form 與可見 UserControl，沒有設計時例外；執行程式時所有動態內容、事件與版面行為維持正確。

## 7. 補齊手寫正式程式碼文件

1. 掃描正式程式碼的手寫型別與成員，排除 Designer、資源自動產生碼、建置輸出與測試程式。
2. 僅為函式（包含建構函式）加入繁體中文 XML 文件註解（`///`），說明契約、參數、返回值、副作用與例外；類別、列舉、屬性、事件及重要欄位以一般單行註解（`//`）說明。
3. 只在關鍵判斷、幾何演算法、持久化交易、Undo/Redo 邊界與不直觀狀態變更加入單行註解。
4. 用可編譯的 XML 文件語法處理參數、返回值、例外與參照；不改變成員可見性或程式行為只為生成文件。

**驗證：** 自動掃描沒有遺漏目標成員，Release x64 建置無 XML 語法警告，抽查註解與實際契約一致。這些機械式文件變更與功能變更分開提交。

## 8. 整合、桌面驗收與 GitHub 交付

1. 執行全部非互動測試、Release x64 建置、JSON 往返、資料庫重開與必要的便攜發佈檢查。
2. 在 100%、150%、200% DPI 操作圖片頁與標註頁，檢查縮圖、收合圖示、工具圖示、虛線框選、畫筆閉環、鍵盤連發與新增標註集卡片。
3. 在 Visual Studio 逐一開啟全部 Form 與可見 UserControl Designer，記錄成功、錯誤或尚待使用者驗證的結果。
4. 依功能、Designer 與全面註解分開提交；每次提交前檢查暫存差異，不納入參考畫面或無關檔案。
5. 推送 `annotation-geometry-ui-designer` 並建立指向 `main` 的 Draft PR，分別附上自動測試、建置、CI、Designer 與桌面驗收證據。

**驗證：** Draft PR 只包含本規格範圍，已完成與待使用者驗收項目清楚分開；在另行收到明確合併指示前不合併 `main`。

## 主要失敗情境

- 最小生成樹的邊長正確，但編碼回單一路徑時洞繞行或橋接往返錯誤；必須用填色遮罩、面積與 JSON 重開驗證，不只檢查邊集合。
- 等距時無法從路徑穩定辨識既有邊，導致新增洞後路徑不必要跳動；以重複執行、儲存重開與等距樣本驗證。
- 多洞候選線數量與輪廓點數相乘，造成介面再次卡住；先量測分段耗時，不以背景執行掩蓋超時。
- 縮圖收取滑鼠時仍誤觸畫布繪製，或縮圖與捲軸使用不同邊界；以實際手勢與視角狀態驗證。
- 鍵盤連發被記成數十個 Undo，或焦點移動導致群組未完成；以按下、連發、放開與失去焦點建立明確完成邊界。
- 上下鍵同時切圖與移動物件；以「是否有 OBD／SEG 選取」作為唯一分流條件，並在文字焦點時停用兩者。
- Designer 搬移後事件重複接線、z-order 改變或動態控制項未初始化；每搬移一個畫面就執行互動測試與桌面檢查。
- 大量 XML 文件註解遮蔽功能差異或與程式行為不一致；獨立提交、只描述契約與不直觀邏輯，並以編譯與抽查控制。
