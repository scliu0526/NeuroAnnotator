# 標註介面、SEG 效能與空洞橋接實行計畫

## 範圍與閘門

- 依[增量正式規格](../specs/annotation-ui-seg-performance.md)實作；附圖只作版面參考，不新增模型或訓練功能。
- 全程使用 `annotation-ui-seg-performance` 分支。文件與實作完成後推送分支並建立 Draft PR；使用者親自明確確認前不得合併 `main`。
- 本次可在指定電腦本機唯讀使用現有真實素材作效能驗收；CI、PR 附件及可攜式 ZIP 只使用合成／匿名素材。此例外不延伸至其他工作。
- 每階段記錄測試素材版本、Release x64 建置結果、失敗案例、效能原始數據及仍未達成的門檻。不得以主觀「看起來順暢」替代量測。

## 1. 基線與瓶頸定位

1. 在目前 Windows 電腦以 Release x64 和本次允許的素材，重現畫筆、筆刷放開後的延遲；另外建立約 17,000 點完成操作案例。
2. 分別量測畫布事件、幾何聯集／差集、資料庫提交、Undo 記錄及重繪的耗時與配置量；重複操作以觀察熱／冷路徑。
3. 紀錄完成輸入至持久化且可見結果的逐筆時間，並確認處理期間視窗仍能重繪、接收切圖要求。

**驗證：** 有可重跑的慢案例與原始量測數據；若瓶頸與原先推測不符，依量測修正後續修法，不先加入推測性的背景工作抽象層。

**規劃階段初測（2026-10-07）：** 在目前電腦的 Release x64 建置，以合成 1,000×1,000 圖片及 17,000 個路徑點量測，現行未合併的 SEG 筆畫完成約 29.2 秒。試作將逐點資料庫寫入置於單一交易並重用預備命令後，筆畫與後續筆刷操作的同一測例均在 1 秒內完成。這項試作未納入本次文件提交；正式實作時仍須分段量測、補上重複執行與真實素材驗收，不能只依單次數值判定達標。

## 2. SEG 完成流程及空洞橋接

1. 針對實測瓶頸縮減重複區域掃描或幾何運算；若須移出 UI 執行緒，運算使用不可變輸入，並保持同一專案資料庫操作序列化。
2. 完成操作維持「一次有效提交、一次 Undo 記錄、畫布對應同一圖片與標註集」。運算中按上下鍵先記住目標；成功儲存後切換，失敗時留在原圖並明示錯誤。
3. 對新生成或幾何編輯後重新生成的空洞，尋找內外輪廓邊段間最短的合法橋接。允許插入邊上整數端點，排除穿出標註實體或穿過其他洞的線段；等距時結果穩定。未修改的匯入路徑不重新橋接。

**驗證：** 現有素材與 17,000 點壓力案例每筆完成不超過 1 秒；UI 不進入無回應狀態。聯集、擦除分裂、洞、凹形外圈、多洞、Non-Zero、自交及 JSON 往返均維持正確。若效能門檻失敗，保留量測並繼續修正，不宣稱完成。

## 3. 共用圖片工作區與版面

1. 將圖片與標註頁的左側清單和圖片選取整合；共用倍率、平移與目前圖片。圖片頁呈現原圖，標註頁呈現目前標註集的疊圖。
2. 將縮放控制移至圖像上方、工具與類別移至右側，工具改用圖示和停留提示；類別清單上方放新增類別入口。
3. 依 CLA／OBD／SEG 顯示允許的工具；OBD／SEG 進入時為選取模式。建立標註集成功後選取新集。
4. 版面優先保留畫布高度與兩頁一致尺寸；高 DPI 或窄視窗允許欄寬縮小與內容捲動，但左側清單及右側工具仍可見。

**驗證：** 相同正常視窗下標註畫布高度至少比原版增加約 25%，圖片頁顯示區同尺寸；在 1366×768、100%～200% DPI 下重要控制項不截斷且仍可操作。新增、切換、改名及同名標註集依內部 ID 正確隔離。

## 4. 操作、顯示與資料集數量

1. 上下鍵依目前可見順序切圖；搜尋時不跳離原圖，文字欄位保留方向鍵與 Ctrl+A。標註頁的 Ctrl+A 選目前圖片／標註集全部物件；Ctrl+點擊只在選取模式生效。
2. F 切適合視窗，實際倍率於所有縮放來源及視窗尺寸變動後更新。每軸平移在圖片小於視窗時置中，在圖片大於視窗時夾至圖片邊緣。
3. SEG 筆刷、線型與橡皮擦共用原圖像素寬度；筆刷與線型預覽、完成結果對照幾何寬度與縮放倍率。
4. 透明度滑條作用於 OBD 填色與 SEG 填色、筆刷、線型；外框、文字、控制點維持可見。每次切換標註集或重新開啟專案回到預設 40%，不寫入 JSON。
5. 資料集分配頁對 OBD／SEG 顯示目前標註集的物件數，使用批次查詢避免 10,000 張清單逐列查庫。

**驗證：** 以鍵盤焦點、快速切圖、非同步載入取消、空圖、缺圖、搜尋排除、排序邊界及多選案例驗收。數量須在新增、合併、擦除分裂、刪除、Undo/Redo、匯入及切換標註集後正確更新。

## 5. 回歸、效能與交付

1. 執行 Release x64 建置、所有非互動自動測試、JSON 往返及可攜式 ZIP 檢查；以匿名素材做 GitHub CI。
2. 在目前電腦完成真實鍵鼠操作、處理中切圖、畫布視角同步、低透明度可選取、DPI、記憶體及 1 秒完成時間測試。
3. 整理匿名截圖、測試與效能原始數據及未達標風險；推送分支，建立 Draft PR 供使用者親自驗收。

**驗證：** 無已知可重現功能缺陷，所有本次正式規格的驗收案例通過，Draft PR 未合併。使用者明確確認前，合併閘門保持關閉。

## 可能失敗的情境

- 大量同類別區域聯集、空洞橋接與 Undo 快照使完成時間超過 1 秒：以每段耗時定位；不得只把運算搬到背景後宣稱解決卡頓。
- 快速切圖與背景載入交錯導致舊圖或舊標註顯示在新圖：以圖片及標註集不可變識別碼比對提交與顯示目標。
- 背景幾何與 SQLite 共用連線造成鎖定、錯誤 Undo 順序或重複提交：對專案寫入序列化並測試失敗回滾。
- GDI 預覽筆觸與幾何膨脹的端點／接合形狀不一致：比較原圖像素寬度及輸出遮罩，不只比較控制項數值。
- 最近橋接穿越其他洞、凹陷外圈或整數化後交叉：測試合法性、填色面積、洞及 JSON 往返。
- 高 DPI 下三欄互相擠壓：在指定解析度逐級檢查左清單、畫布與右工具仍可操作。
- 匿名 CI 通過但真實素材仍慢：本機效能驗收是獨立硬性閘門，數據不得放入公開附件中的真實影像內容。
