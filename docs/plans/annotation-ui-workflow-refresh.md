# 標註介面與匯入工作流程實行計畫

## 範圍與完成條件

- 以[增量正式規格](../specs/annotation-ui-workflow-refresh.md)與 [ADR-0005](../adr/0005-serialize-project-import-jobs.md)為驗收契約。
- 工作分支為 `annotation-ui-workflow-refresh`，從最新 `origin/main` 的獨立 sibling worktree 建立；原工作目錄的未提交內容不得搬移、提交或清理。
- 本計畫先交付文件與 GitHub Issue。後續程式修改、Draft PR、Designer／Windows 桌面驗收與合併是分開的核准關卡。
- 完成條件包括 Release x64 建置、全部自動測試、GitHub Actions、Visual Studio Designer、Windows 實際操作及 100%／150%／200% DPI；任一證據不得取代其他關卡。

## 1. 建立基線與失敗案例

1. 記錄新 worktree 的分支、HEAD、乾淨狀態、Release x64 建置及全部測試結果；原工作目錄另行記錄狀態，證明沒有被改動。
2. 盤點所有正式手寫函式、固定 Designer 控制項事件、屬性頁不可見自訂事件、三種匯入入口、SEG 工具完成事件、資料集切分接縫及動態類別列。
3. 在修改前增加或固定外部行為案例：五種工具的完成時 Ctrl、隱藏標註擦除、匯入 FIFO、切分所選範圍、類別列與左右欄配置。

**驗證：** 每個需求缺口都有可穩定重現的失敗；基線失敗與本次新增失敗分開記錄，沒有先假定原因。

## 2. 建立匯入工作生命週期

1. 建立不可變的匯入工作描述，分別保存圖片檔案路徑清單、資料夾與遞迴選項、或 JSON 路徑；工作固定綁定加入時的專案工作階段。
2. 建立單一專案範圍 FIFO 執行器，集中管理等待中、執行中、已完成、失敗與已取消狀態；任何時刻只允許一項進入專案寫入。
3. 實作十筆活動工作上限、二十筆已結束歷史、非致命續跑、致命停止、等待取消、圖片／資料夾執行取消及 JSON 原子寫入不可取消。
4. 將現有圖片、資料夾及 JSON 匯入流程包成工作執行端，不複製匯入、驗證、進度、部分成功或交易邏輯。
5. 建立工作狀態快照與 UI 通知，使視窗只呈現狀態及發出命令，不直接擁有佇列規則。

**驗證：** 三種類型混合排隊仍保持 FIFO 與單一寫入；上限、歷史淘汰、取消、來源消失、部分成功、JSON 失敗原子性及非致命續跑均通過可控制的整合測試。

## 3. 協調專案生命週期與命令啟用

1. 佇列有等待或執行工作時鎖定建立、開啟、另存及專案替換；三個匯入入口只在沒有專案或達十筆上限時停用。
2. 允許頁面切換、圖片瀏覽與既有單張圖片標註；停用刪圖、資料集批次操作、匯出、備份還原及其他全域命令。以單一狀態計算更新所有入口，避免完成或失敗後漏恢復。
3. 關閉主視窗時顯示執行中與等待中數量。確認關閉後移除等待工作、取消可取消工作；JSON 寫入中等待完成。取消關閉時不改變佇列。
4. 專案關閉後清除工作歷史與佇列視窗內容，不將工作狀態寫入專案資料庫或設定檔。

**驗證：** 每個工作狀態轉換都核對命令啟用矩陣；切換專案不可穿透鎖定，關閉不留下背景寫入、已處置專案存取或半份 JSON。

## 4. 建立頁面入口與匯入佇列視窗

1. 在圖片清單上方加入「匯入圖片」與「匯入資料夾」，在標註頁標註集操作之後加入「匯入標註 JSON」；移除原三個匯入選單入口，保留同一底層工作建立流程。
2. 以 Designer 建立單一 modeless 匯入佇列視窗、可捲動卡片容器、清除已完成與關閉按鈕；第一筆工作自動顯示，專案選單提供重新開啟入口。
3. 以 Designer 建立匯入工作卡片 UserControl，顯示類型、來源、狀態、順位或進度、摘要、取消、詳細資料展開／收合及適用的「查看匯入圖片」。動態卡片只透過狀態快照刷新。
4. 圖片與資料夾工作保存成功新增的圖片 ID。查看時切到圖片頁、清除阻擋篩選、取代目前多選、捲到並顯示第一張；已刪除 ID 靜默略過，全數不存在時停用並以 ToolTip 說明。

**驗證：** 視窗始終只有一個實例；關閉視窗不取消工作；工作卡片順序、狀態、按鈕與詳細資料正確；大量卡片可捲動且二十筆歷史不截斷；批次導覽只選取本工作仍存在的成功圖片。

## 5. 擴充 SEG 完成時 Ctrl 擦除

1. 在畫布的矩形、圓形、畫筆、筆刷與線形完成邊界取得當下 Ctrl 狀態，將完整預覽轉成「新增」或「擦除」命令；操作途中按鍵變化不提交片段。
2. 將矩形、橢圓、多邊形及有寬度筆畫轉成既有 SEG 差集核心可接受的實際幾何，只處理目前類別。沿用碎片、洞、橋接、整數化、邊界、交易與 Undo/Redo。
3. 移除標註可見性對幾何擦除提交的限制，但不恢復隱藏既有標註的命中、選取或變形；無命中時不存檔、不新增歷史、不提示。
4. 更新畫布游標繪製：十字右下角 Ctrl `−`，筆刷／線形圓環右下角 `+`／`−`，橡皮擦 `−` 右下角；按鍵變化時立即重繪，尺寸依 DPI 且不遮落點。

**驗證：** 五種工具的 Ctrl 在開始、途中、完成前按下／放開組合均由完成瞬間決定；同類別差集、他類別不變、洞與碎片、隱藏標註、無命中、Undo/Redo、重開及 JSON 語意通過。

## 6. 新增切分所選並重排資料集頁

1. 將資料集控制項重排為左側篩選與清單、右側固定操作欄；右欄分成隨機切分、手動分配、Dataset Retest，並於高 DPI 或低高度提供垂直捲動。
2. 隨機切分區保留 train／test 聯動比例，加入「切分所選」與「切分全部」。沒有明確清單選取時停用前者，確認訊息顯示模式及實際可用圖片數。
3. 將切分用例擴充為明確目標圖片 ID 範圍；規劃器仍以傳入候選套用既有隨機、test 至少三張、每類盡量保留十張 train 與警告規則。
4. 持久化只覆寫目標範圍的資料集狀態，保留範圍外狀態與所有 Retest；整次形成單一完成操作及 Undo/Redo。
5. 手動分配排成 Train／Test、未分配／不使用兩列；Retest 區只保留設為 Retest，清除 Retest 維持右鍵選單。

**驗證：** 選取、篩選、缺失圖片、少量候選、類別不足、無標註圖片、警告、範圍外不變、Retest 保留及單次 Undo/Redo 均有規劃器與儲存整合案例；1366×768 與高 DPI 清單仍有非零可用寬度。

## 7. 更新類別列顯示

1. 將動態類別按鈕改為單列互動控制項，左側顯示 DPI 縮放的圓角色塊、右側顯示單行類別名稱；整列保留原選取／套用行為與右鍵選單。
2. 作用中類別以淡色背景與左側系統強調色線表示，不讓類別色同時承擔選取語意。長名稱省略並以 ToolTip 顯示全文。
3. 確認 CLA 的目前圖片類別、OBD／SEG 落筆類別、已選物件改類別，以及改名、改色、刪除後刷新均維持既有契約。

**驗證：** 三種標註集、長名稱、極亮／極暗類別色、切圖、切集、改色與右鍵操作均正確；色塊圓角、文字位置、選取提示在 100%／150%／200% DPI 可辨識。

## 8. 搬移 Designer 可見事件

1. 逐一在 Visual Studio Designer 選取固定控制項，確認屬性事件頁實際可見的事件；只有這些事件改由 Designer 接到具名處理函式。
2. 保留屬性頁不可見的畫布、資料集、圖片瀏覽與動態卡片自訂事件在一般程式碼中，不變更其委派型別或資料契約。
3. 每搬移一個畫面就建置並執行相關互動測試，確認事件只接一次，沒有因 Designer 重寫遺失或重複觸發。

**驗證：** 受影響 Form／UserControl 可在 Designer 無錯誤開啟；固定事件可從屬性頁看見並雙擊到具名函式；自訂事件例外清單與程式搜尋結果一致。

## 9. 整理 XML 文件註解

1. 盤點正式 `src` 手寫函式與建構函式，依專案層次分批補成繁體中文多行 XML 文件；參數、回傳值、副作用與實際例外按契約說明。
2. 完全沿用介面或基底契約者使用 `inheritdoc`；任何新增副作用、例外或語意差異者改寫完整文件。排除 Designer、產生碼、測試與輸出。
3. 文件整理獨立提交，不順便重構、改名、重新格式化或清除既有無關程式。

**驗證：** 盤點沒有漏掉手寫函式；XML 有效、建置及 IntelliSense 正常；每一行差異都只屬於文件需求或由文件整理造成的必要格式變更。

## 10. 整合驗收與 GitHub 交付

1. 執行 Release x64 建置、全部 MSTest、SEG 幾何遮罩、專案儲存、JSON 原子性、資料集規劃、WinForms 版面與發佈檢查。
2. 在 Visual Studio 逐一開啟受影響 Designer，核對事件屬性與主要控制項；在 Windows 實際操作匯入排隊／取消／關閉、Ctrl 擦除、切分所選、類別列及批次圖片導覽。
3. 於 1366×768 與一般桌面尺寸、100%／150%／200% DPI 記錄游標、按鈕、卡片、右側操作欄、長文字、省略與捲動結果。
4. 依功能分成文件、匯入佇列、Ctrl 擦除、資料集／類別 UI、Designer 事件與 XML 文件等可獨立審查提交。只暫存核准路徑。
5. 推送 `annotation-ui-workflow-refresh`，建立指向 `main` 的 Draft PR，附上已通過、失敗及仍待使用者桌面驗收的證據。只有使用者明確指示才轉 Ready 或合併。

**驗證：** 自動測試、CI、Designer 與桌面驗收各有獨立結論；Draft PR 差異不包含原工作目錄的既有未提交內容，也沒有意外合併。

## 主要失敗情境

- 工作按 FIFO 顯示但實際由三個背景流程平行寫入；以執行時序與單一寫入互斥測試證明，而不只看卡片順序。
- 取消圖片匯入後工作尚未完全停止就啟動下一項，造成序號或初始化競爭；下一項只能在前項安全結束後開始。
- JSON 顯示可取消但交易已開始，造成使用者誤以為取消成功；寫入開始後卡片必須立即反映不可取消狀態。
- 佇列完成／失敗後專案命令沒有恢復，或關閉視窗誤取消背景工作；以完整狀態轉換矩陣驗證。
- 批次導覽依檔名搜尋而選到舊圖片或撞名項目；必須保存並使用實際成功新增的不可變圖片 ID。
- Ctrl 在筆刷途中改變時被切成新增與擦除兩筆；以完成前切換按鍵的幾何與歷史數量驗證。
- 標註隱藏時畫布因既有保護條件拒絕 Ctrl 擦除或橡皮擦；此例外需有明確回歸測試。
- 切分所選把目前篩選可見列當成目標，或儲存層仍覆寫全體；測試同時檢查候選輸入與範圍外資料逐筆不變。
- Designer 接線與原程式接線同時存在，造成單次點擊執行兩次；每個搬移事件需搜尋及互動驗證只接一次。
- 全面 XML 文件變更與功能差異混在同一提交，讓審查漏看行為；以提交分界與差異統計控制。
- 右側資料集欄、垂直卡片或類別名稱在高 DPI 截斷，卻因 CI 綠燈被誤判完成；Windows/DPI 驗收是合併前獨立硬門檻。
