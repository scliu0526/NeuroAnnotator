# 標註工作流程、專案工作佇列與畫布互動實行計畫

## 範圍與完成條件

- 以[增量正式規格](../specs/annotation-workflow-queues-and-canvas-fixes.md)與 [ADR-0006](../adr/0006-serialize-project-jobs.md)為驗收契約。
- 工作分支為 `annotation-workflow-queues-and-canvas-fixes`，從最新 `origin/main` 建立；本階段先交付文件與 GitHub Issue，功能實作、Draft PR、桌面驗收與合併是後續分開關卡。
- 完成條件包含 Release x64、全部非互動測試、手動效能測試、GitHub Actions、Visual Studio Designer、Windows 操作及 100%／150%／200% DPI。任一證據不得取代其他關卡。
- 每一行功能差異必須可追溯到正式規格；不順便重構鄰近程式或加入暫停、重試、持久化等未核准能力。

## 1. 建立基線與失敗案例

1. 記錄分支、HEAD、乾淨狀態、Release x64 建置、全部非互動測試及既有手動效能測試結果。
2. 盤點匯入工作狀態、匯入卡片、三種匯出入口、專案命令啟用矩陣、JSON 解析／寫入、畫布游標／縮圖／預覽及資料集版面接縫。
3. 修改前新增或固定外部失敗案例：Ctrl 重繪效能、線形平頭、圖片外游標、手勢縮圖、固定寬度卡片、JSON 目標／模式、混合 FIFO、匯出取消、刪除名稱、透明度階距及資料集並排。

**驗證：** 每個需求缺口都有可重現證據；基線既有失敗與本次新增失敗分開記錄，不以推測原因直接修改。

## 2. 更新領域詞彙與序列化決策

1. 將匯入佇列提升為專案工作佇列，定義專案工作、匯入工作與匯出工作。
2. 以 ADR-0006 取代 ADR-0005，記錄混合匯入／匯出使用同一 FIFO、禁止平行專案 I/O 及採單一視窗的取捨。
3. 將正式規格、增量計畫、測試計畫與已知風險互相連結。

**驗證：** CONTEXT 只保存領域語言與不變條件；實作細節留在規格／計畫；舊 ADR 明確標示被取代且歷史理由仍可閱讀。

## 3. 建立專案工作佇列核心

1. 建立不可變專案工作描述及統一狀態快照，涵蓋三種匯入與三種匯出。
2. 將既有匯入 FIFO 擴成單一混合執行器；任何時刻最多一項進入專案 I/O，跨類型依加入時間排序。
3. 實作十筆活動上限、五十筆終止歷史、完成但有警告、直接失敗歷史、等待取消、非致命續跑與致命停止。
4. 以集中狀態計算專案命令、目標標註集精準鎖及關閉協調，避免工作結束後漏恢復。
5. 保持工作與歷史為執行期狀態，不新增資料庫結構或重啟恢復。

**驗證：** 混合工作時序證明只有一項執行；活動／歷史上限、取消、失敗續跑、專案替換防護、精準標註集鎖與關閉安全均通過可控制的生命週期測試。

## 4. 建立 JSON 匯入預檢與設定流程

1. 未選目前標註集時停用入口；選檔後在背景完整解析並驗證格式、型別、類別、圖片對應、尺寸、幾何及未知欄位。
2. 建立設定視窗，以右側樹狀摘要顯示類別數量、類別名稱與來源 Set 狀態，不顯示完整原始 JSON；型別不符或致命預檢錯誤直接建立失敗卡片。
3. 將標註／類別與資料集狀態分成獨立核取及唯讀下拉模式；依 CLA 或 OBD／SEG 顯示合法選項；至少選一組。
4. 列出未知欄位並要求主動同意；顯示不可 Undo/Redo 警告並要求再次確認。取消不建立工作。
5. 工作要求保存目標標註集 ID、當時名稱／型別、來源路徑、未知欄位同意及模式，不保存 JSON 內容。

**驗證：** 入口啟用、預覽、模式矩陣、未知欄位、型別錯誤、取消、不可復原確認及目標固定都有主視窗／設定視窗行為測試；UI 全程保持回應。

## 5. 將 JSON 原子匯入目前標註集

1. 執行時重新讀取並完整驗證來源；任何漂移、型別變更或新未知欄位依已確認規則失敗。
2. 先建立同名既有類別與 JSON 類別的大小寫敏感映射；既有顏色優先，缺少類別使用 JSON 顏色。
3. 實作 CLA 空白／取代及 OBD／SEG 空白／追加／取代範圍；追加物件取得新 ID 並放在最上層，不觸發 SEG 聯集。
4. 實作資料集狀態只加入未分配／取代 JSON 對應圖片；所有 Retest 與未列出圖片保持。
5. 將類別、標註與資料集變更包在單一交易；不建立歷史項目，失敗時完整回滾。
6. 工作執行期間只鎖定目標標註集，完成後刷新類別、畫布、圖片摘要與資料集頁。

**驗證：** 三型別、全部模式、空標註、同名不同色、缺少類別、層級、重疊、資料集狀態、Retest、來源漂移、失敗回滾、重開及 JSON 往返均有儲存整合案例；成功前後 CanUndo/CanRedo 不因匯入新增項目。

## 6. 建立安全匯出工作

1. 將標註 JSON、所選圖片 ZIP、全部圖片 ZIP 改為工作描述；輸出路徑與目標識別排隊時固定，內容依執行開始狀態取得。
2. 為圖片 ZIP 加入逐檔進度與取消檢查；為 JSON 提供不確定進度及發布前取消語意。
3. 所有輸出先寫同目錄暫存檔，成功後以唯一最終名稱發布；失敗／取消清理暫存。
4. 缺失圖片略過並產生完成但有警告；零張可用時失敗且不產生 ZIP。
5. 保存實際輸出路徑，提供開啟所在資料夾並選取檔案；路徑失效時停用並說明。

**驗證：** 前序匯入可見、所選 ID 固定、全部範圍執行時解析、進度、取消、暫存清理、撞名、缺失、零可用、結果導覽及輸出內容正確。

## 7. 重建統一工作佇列視窗與選單

1. 將既有匯入卡片與視窗改為混合工作卡片及單一工作佇列視窗；固定 DPI 感知寬度、高度可調、只垂直捲動。
2. 卡片依工作種類顯示來源／目標、狀態、真實或不確定進度、摘要、取消、詳細資料、查看匯入圖片或開啟輸出資料夾。
3. 來源使用省略與 ToolTip；詳細錯誤使用可選取、換行、限高、垂直捲動控制項。
4. 第一筆工作自動顯示；關閉視窗只隱藏介面。清除已結束同時支援兩種工作，不影響活動工作。
5. 將主選單重排為專案、工作、管理、說明，並更新完整啟用矩陣。

**驗證：** 單一視窗、卡片寬度、無橫向捲軸、五十筆歷史、長文字、DPI、按鈕狀態、結果失效、Designer 及選單精確子項均通過。

## 8. 修正 Ctrl 效能與線形預覽

1. 以真正畫布、17,000 點素材及五種工具量測一般／Ctrl 模式的事件、重繪裁切、標註渲染、游標與預覽成本；橡皮擦作對照。
2. 只針對量測瓶頸減少配置、重複計算或過大重繪範圍，不改變完成瞬間 Ctrl、40% 預覽、類別隔離或幾何差集契約。
3. 將線形尚未完成預覽的起訖端與連接改為圓形，並修正局部重繪邊界以包含圓頭。
4. 建立 Release x64 效能量測，保留平均、95 百分位與最大停頓原始數據。

**驗證：** 五種工具一般／Ctrl 平均至少 60 FPS、p95 不超過 33.3ms、無超過 100ms 單幀；預覽圓頭與實際結果在筆寬、縮放、Ctrl 及邊界案例像素一致。

## 9. 修正畫布游標與縮圖生命週期

1. 分離實體指標命中與標註座標限制：圖片外使用系統箭頭且新左鍵按下不開始標註；從圖片內開始並持續按住拖到外面的移動點仍投影至最近圖片邊界。
2. 對 OBD 矩形與全部 SEG 繪製／擦除工具套用規則；選取工具維持既有行為。
3. 建立一致的進行中手勢狀態，讓縮圖與收合按鈕從開始到完成／取消保持隱藏。
4. 讓完成、Esc、失焦、切圖、切集、切工具、切頁與錯誤清理都通過同一恢復出口；沒有手勢時縮圖保持最高命中優先。

**驗證：** 圖片四邊／四角、畫布空白、縮圖、線形跨點、多邊形跨點、所有取消出口及提交幾何均由真實滑鼠事件測試；縮圖現有適合視窗判定不變。

## 10. 完成其餘 UI 修正

1. 將透明度滑桿與數值欄限制為 0..100 的十倍數，非十倍數四捨五入；維持預設 40%。
2. 保留封閉形狀在 0% 的既有不透明輪廓；筆刷／線形／單點未選取時允許完全消失，不新增幾何外框。
3. 將 Train／Test 比例及切分所選／全部各放入 50% 兩欄版面，調整 DPI 感知操作欄寬度但保留左側清單。
4. 以真實 UI 重現標註集刪除；鎖定目前 ID，處理 false 回傳並顯示目前目標名稱不符警告。

**驗證：** 透明度輸入與像素、兩組並排、1366×768、高 DPI、選取 A 輸入 B／大小寫／重名及正確刪除均通過。

## 11. 整合驗收與 GitHub 交付

1. 執行 Release x64、全部 MSTest、手動效能測試、可攜式發佈檢查與 GitHub Actions。
2. 在 Visual Studio 開啟所有受影響 Form／UserControl，確認 Designer 無例外、事件沒有重複接線。
3. 在 Windows 實際操作混合排隊、取消、來源漂移、JSON 模式、匯出結果、Ctrl 擦除、圖片外游標、縮圖、透明度、資料集版面及刪除警告。
4. 於 1366×768 與一般桌面尺寸、100%／150%／200% DPI 保存版面、捲動、游標、圓頭與卡片證據。
5. 依文件、佇列核心、JSON 匯入、匯出、佇列 UI、畫布、其餘 UI 與驗收文件分開提交；推送分支並建立 Draft PR。

**驗證：** 自動測試、CI、效能、Designer、Windows 與 DPI 各有獨立結論；未通過或尚待使用者驗收的項目明示；只有使用者再次明確批准才合併 main。

## 主要失敗情境

- 畫面顯示同一佇列，但匯入與匯出仍由不同背景工作同時存取專案；以跨類型執行時序與互斥測試證明。
- 預檢成功後來源被替換，工作仍依舊摘要寫入；執行時必須重新驗證並依新內容失敗或執行。
- JSON 取代先刪除資料再遇錯誤，留下部分類別或圖片；以故障注入驗證單一交易回滾且無 Undo 項目。
- CLA 顯示不合法的追加所有模式，或 Retest 被資料集匯入改寫；以型別模式矩陣與逐筆狀態比較驗證。
- 匯出取消後最終檔或暫存檔仍存在；以等待取消、壓縮中取消、JSON 發布前取消及程序關閉驗證。
- 完成但有警告被當成一般成功而隱藏缺失圖片；卡片狀態、摘要及 ZIP 內容必須一致。
- Ctrl 平均 FPS 達標但間歇停頓；保存原始幀資料並同時檢查 p95 與最大停頓。
- 線形改成圓頭但局部裁切仍按平頭估算，造成端點殘影；像素回歸同時檢查新舊端點區域。
- 圖片外顯示一般箭頭但新左鍵按下仍誤開始標註，或圖片內開始後拖出圖片便中斷／幾何越界；起點命中、持續手勢與提交結果必須分別驗證。
- 縮圖在 Esc、切頁或例外後未恢復，或在線形／多邊形兩點之間閃回；所有完成與取消出口共用狀態測試。
- 固定工作視窗寬度仍因 FlowLayoutPanel 自動配置產生橫向捲軸；以 1、10、50 張卡片及 100%～200% DPI 驗證。
- 刪除流程其實已在儲存層拒絕錯誤名稱，卻誤改底層並造成新回歸；先從真實 UI 證據定位，再做最小修改。
