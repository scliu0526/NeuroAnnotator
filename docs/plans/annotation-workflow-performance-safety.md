# 標註工作流程安全與效能實作計畫

## 範圍與完成條件

- 以[增量正式規格](../specs/annotation-workflow-performance-safety.md)、[領域脈絡](../../CONTEXT.md)與 [ADR-0002](../adr/0002-seg-geometry.md)為驗收契約。
- 工作分支為 `annotation-workflow-performance-safety`；所有修改、測試與提交均在原專案路徑 `D:\Codex\Neurocle` 的該功能分支進行，不建立額外 worktree。
- 保留原工作樹既有未提交內容；不得直接修改或合併 `main`。
- 完成條件包含 Release x64、全部非互動測試、指定效能案例、WinForms 實際操作、Visual Studio Designer 與 GitHub Actions。效能硬門檻未通過時不得宣稱完成。
- 每一行功能差異必須能追溯至規格；不順便重構相鄰程式或加入未核准能力。

## 1. 固定基線、量測點與失敗案例

1. 記錄分支、HEAD、工作樹狀態、Release x64 建置、全部非互動測試及現有效能測試結果。
2. 建立可重現案例：擦除出洞後平移、10 個各約 17,000 點 SEG 區域拖曳與提交、冷／暖切圖、快速連續切圖及同尺寸／異尺寸視角。
3. 分段量測拖曳事件、預覽渲染、幾何提交、資料庫更新、歷史建立、圖片解碼、標註查詢、摘要刷新及 UI 套用。
4. 先讓新增回歸案例在現況失敗，再依證據縮小根因；既有失敗與本次新增失敗分開記錄。

**驗證：** 每個缺口都有可重現證據與原始時間資料；不以推測原因直接修改。

## 2. 建立每工作階段單例啟動閘門

1. 在建立主視窗及安裝啟動診斷之前取得目前 Windows 登入工作階段的單例所有權。
2. 第二份程序顯示已在執行提示後結束，不嘗試啟用既有視窗。
3. 第一份程序持有所有權到訊息迴圈結束，並保留現有例外處理與啟動流程。

**驗證：** 同工作階段第二次啟動被拒絕；第一份結束後可重啟；不同 Windows 工作階段不互相阻擋；啟動失敗不留下永久鎖定。

## 3. 統一圖片清單欄位與清除互動

1. 將清單欄位依頁面與標註型別配置：圖片頁只顯示序號與檔名；標註、資料集分配及完成／匯出頁顯示類別、資料集與 Retest，OBD／SEG 另顯示標註數量且零數量留白，CLA 不顯示標註數量；所有適用欄位不依賴水平捲動即可看見。
2. 在標註頁、資料集分配頁與完成／匯出頁共用右鍵命中規則：只有命中已選取列才開啟，且不得改變既有多選。
3. 選單顯示選取數量，固定提供清除 Retest、清除類別、清除資料集三個命令；圖片頁不提供清除選單。
4. 三個命令皆先顯示命令、標註集與圖片數量並要求確認；無實際差異時不建立歷史。
5. 清除後只刷新受影響的清單摘要、目前畫布與資料集狀態。

**驗證：** 單選、多選、空白、未選取列、取消、無變更及三種標註集均有 UI 與儲存整合測試；右鍵前後選取集合完全相同。

## 4. 將 SEG 純平移與一般幾何更新分離

1. 以區域識別碼及共同整數位移表達滑鼠或鍵盤完成的純平移，不再傳入一般幾何重建入口。
2. 提交前一次驗證整組移動後仍在圖片邊界內；任一區域越界時依既有規則限制整組位移。
3. 以座標增量更新全部點位，保留身分、類別、型別、點序、既有空洞橋接、相對順序與置頂規則。
4. 一次拖曳或一段連續方向鍵操作建立一筆歷史；Undo／Redo 以相反位移重播。
5. 縮放、旋轉、擦除及其他改變相對幾何的操作仍沿用現有合法橋接流程。

**驗證：** 擦除成洞後的滑鼠／鍵盤平移均成功，儲存點位等於原路徑加共同位移；Undo／Redo 精確往返；失敗操作不改變資料或歷史。

## 5. 消除大量 SEG 拖曳與提交延遲

1. 拖曳期間只保存共同位移及受影響區域，不在每一幀複製或重建約 170,000 個點。
2. 重繪範圍只涵蓋舊、新幾何聯集與必要控制項，不改變顯示精度、命中測試或正式座標。
3. 放開或鍵盤提交只執行一次邊界驗證、增量持久化、歷史記錄及必要 UI 更新。
4. 保存平均 FPS、p95 幀時間、最大幀時間及提交端到端時間的原始結果。
5. 類別或層級單獨變更只更新中繼資料；新增單一孔洞保留仍合法的既有候選，並依輪廓大小選用精確線段或外框距離下界，延後或省略不可能改善最小生成樹的候選計算。
6. 整體變形遇到無法重新解析的舊版匯入橋接時保留變形點序；不得放寬一般任意幾何修改的合法性。
7. 畫布已完成邊界驗證的純平移提交不在資料層重掃全部點位；一般資料層入口仍保留完整邊界檢查。專案連線在 schema 驗證後使用 WAL，既有保存動作負責 checkpoint。

**驗證：** 固定案例平均至少 60 FPS、p95 不超過 16.7 ms、最大幀不超過 50 ms，滑鼠放開及鍵盤提交皆不超過 500 ms；64 洞新增第 65 洞不超過 500 ms並記錄同點數單一區塊對照，類別變更不超過 100 ms；任何門檻失敗即停止交付。

## 6. 拆分切圖責任並加入有界解碼快取

1. 將目前圖片載入、目前圖片標註查詢與全清單摘要刷新分開；單純切圖不得重查所有圖片摘要。
2. 讓圖片頁與標註頁共用同一份已解碼圖片結果，避免兩個畫布重複讀檔與解碼。
3. 建立有界最近使用快取，至少涵蓋最近三張圖片；替換或移除項目時正確釋放影像資源。
4. 每次切圖具有版本或取消語意；過期工作不得覆蓋最後選取圖片、標註或視角。
5. 載入期間保留舊圖片且不顯示額外訊息，同時停用畫布標註操作；成功後以新圖片及對應標註原子替換。
6. 圖片缺失、解碼失敗或切換專案時清理等待狀態、快取與畫布操作鎖定。

**驗證：** 固定案例冷載入不超過 1 秒、最近三張暖載入不超過 500 ms；快速連續切圖只顯示最後一張；瀏覽 100 張後快取與已解碼圖片數維持上限且無已釋放物件例外。

## 7. 保留或重設畫布視角

1. 在套用新圖片前取得目前畫布倍率、原圖左上角位置及舊圖片像素尺寸。
2. 新舊圖片寬高完全相同時恢復相同倍率與位置，並只依既有邊界規則約束不可達位置。
3. 任一尺寸不同時執行現有適合視窗行為。
4. 圖片頁與標註頁共享同一視角狀態；過期載入不得改寫視角。

**驗證：** 同尺寸圖片往返後倍率與位置不變；寬或高不同時適合視窗；快速切圖、視窗縮放與頁面切換不套用過期狀態。

## 8. 回歸、桌面驗收與 GitHub 交付

1. 執行 Release x64、全部 MSTest、固定效能案例及可攜式發佈檢查。
2. 在 Visual Studio 開啟受影響 Form／UserControl，確認 Designer 無例外、欄位與事件沒有重複接線。
3. 在 Windows 實際驗證單例、右鍵多選、三種清除、空洞平移、拖曳提交、冷暖切圖、快速切圖及視角規則。
4. 檢查 JSON、Undo／Redo、專案重開、資料集分配、完成／匯出摘要及既有非純平移 SEG 操作回歸。
5. 將文件、啟動／清單、SEG 平移、切圖／視角、測試證據分成可審查提交；推送分支並建立 PR。

**驗證：** 自動測試、CI、效能、Designer 與 Windows 實際操作各有獨立結論；未通過項目明示；只有使用者明確批准後才可合併 `main`。

## 主要失敗情境與停止條件

- 單例名稱跨 Windows 工作階段，誤擋其他使用者；以不同工作階段測試驗證作用域。
- 右鍵命中測試先改變選取，造成批次範圍縮小；比較開啟選單前後的選取識別碼。
- 清除命令沒有資料差異仍污染 Undo／Redo；比較操作前後歷史能力與記錄數。
- 純平移仍流入一般幾何更新，重新橋接或重排點位；以逐點差值與故障案例證明未重建。
- 預覽達標但放開仍逐點刪除重建或刷新全部摘要；提交門檻必須涵蓋持久化、歷史與 UI。
- 兩個畫布共享同一可變影像生命週期但其中一方提前釋放；以頁面切換、快取淘汰及關閉測試驗證所有權。
- 載入過期結果回寫圖片或視角；以可控制的亂序完成測試驗證最後選取者勝出。
- 同尺寸視角以控制項尺寸而非圖片像素尺寸判斷；以相同畫布、不同圖片尺寸及相同圖片尺寸、不同視窗尺寸交叉測試。
- 固定效能門檻任一項未通過、測試存在不明回歸或 Designer 無法開啟時，停止 PR 完成宣告並保留證據。
