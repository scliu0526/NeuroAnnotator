# ADR-0001：以 SQLite 與受管理圖片目錄儲存專案

## 狀態

Accepted

## 背景

專案需容納最多 10,000 張圖片、多個彼此隔離的標註集、跨頁 Undo/Redo、部分成功的圖片匯入，以及可驗證的原子 JSON 匯入。參考 JSON 只描述單一標註集，無法完整保存專案編輯狀態。

## 決策

專案由一個 SQLite 資料庫與一個受應用程式管理的扁平圖片目錄組成。資料庫保存不可變識別碼、關聯、排序資訊、雜湊、標註、資料集狀態及必要的原始交換資料；圖片匯入時複製到專案目錄。JSON 僅作匯入與匯出交換格式。

完成操作後自動儲存，同時提供手動儲存與另存新檔。同一專案同時只能由一個應用程式實例開啟。

## 理由

- SQLite 交易可讓跨多張表的編輯、匯入與刪除維持一致。
- 圖片留在檔案系統可避免資料庫膨脹，也保留一般檔案工具的可檢查性。
- 不以 JSON 當專案格式，才能保存多標註集、編輯歷程所需資訊與未匯出的內部狀態。

## 後果

- 必須維護資料庫結構版本、遷移、備份與損毀復原流程。
- 搬移專案時必須一起搬移資料庫與圖片目錄。
- 缺失圖片須以 SHA-256 重新連結完全相同的檔案；無法重新連結時可永久移除其資料。
- SQLite 原生 x64 元件必須隨可攜式套件離線部署。
