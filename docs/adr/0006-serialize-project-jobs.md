# ADR-0006：同一專案的匯入與匯出工作共用單一 FIFO

匯入會修改同一個開啟中的專案，匯出則必須讀到前序工作完成後的一致狀態；分開執行可能讓 ZIP 讀到尚未完成的圖片匯入，或讓標註 JSON 與同一標註集的寫入競爭。Neurocle 因此將匯入與匯出都表示為專案工作，使用專案工作階段內的單一 FIFO 一次執行一項，並在同一個工作佇列視窗中依加入順序呈現。工作只在本次程式工作階段存在，不跨重啟持久化。

## 考慮過的方案

- 匯入與匯出各自維護 FIFO 並平行執行。拒絕此方案，因為資料庫、受管理圖片與輸出快照跨越單一檔案或交易邊界，輸出內容可能不一致。
- 保留兩個佇列但以鎖互斥。拒絕此方案，因為跨佇列先後順序仍不清楚，較晚加入的一類工作也可能讓另一類長期等待。
- 為每筆工作在排隊時建立完整資料快照。拒絕此方案，因為會增加記憶體與排隊延遲，也讓匯出看不到排在它前面的成功匯入。
- 持久化等待工作與歷史。拒絕此方案，因為重啟後來源、輸出路徑與專案工作階段可能已失效，且本次需求只需要目前工作階段的可見進度。

## 後果

- 三種匯入與三種匯出共用全域加入順序，任何時刻最多一項進入專案 I/O。
- 工作視窗、活動上限、歷史、取消、專案生命週期與關閉協調使用同一套狀態；不同工作仍保留各自的原子性、部分成功與取消語意。
- 匯出內容在工作實際開始時讀取，因此能看見前序工作成果；目標識別與使用者選定路徑仍在加入時固定。
- 有活動工作時不得替換目前專案；只鎖定會讓工作目標失效或破壞一致性的命令，不停用整個主視窗。
